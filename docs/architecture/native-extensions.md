# 原生扩展机制：必须保留的能力与宿主契约

本页只记录扩展能力与技术边界。**当前完成/失败状态以[进度主稿](native-progress.md)为准**；两个上游仓库的 37 来源、E01–E06/G0–G5 任务和逐包验收统一在[扩展台账](../migration/upstream-extension-reconstruction.md)维护，不再复制易过期的轮次和卡牌数量。

旧 JS 是否零改动运行尚未决定，按新接口重构保留原有功能不受此项阻塞。目标来自[性能架构 v3.3](../../noname-performance-architecture.md)；本页不另存源码版本、测试失败或整包数量快照。

## 1. 必须保留的能力

用户明确要求“原有的扩展机制也需要有”。保留玩家安装使用与作者独立发布扩展的能力；
不能用“技能都写进内置 Rust、每次重编译客户端”代替。具体旧 JS 是否零改动运行尚待确认，
先按能力保留、允许适配开展设计；不预先删除旧 API 适配选项，也不承诺任意旧脚本直接可用。

| 能力 | 必须支持的行为 | 原生线验收 |
|---|---|---|
| 包生命周期 | 本地导入/安装、发现、启用/禁用、升级/回退、卸载；作者可独立发布 | 新包无需重编译整个客户端；重启状态保留，失败保留旧有效版本 |
| 内容与规则 | 新武将、技能、卡牌、牌堆、规则修改及自定义模式 | 至少一个真实逻辑扩展，包含触发、主动/响应、选择和可恢复状态；不止资源或元数据包 |
| 生命周期与配置 | 注册/初始化、开局/结束处理、可保存的扩展设置 | 确定顺序、依赖/冲突提示、卸载清理；影响规则的配置进入本局内容锁 |
| AI | 扩展决策策略与规则评估 | 只读所属座位合法信息，服从节点/时限/取消预算，不读取真实未知牌 |
| 资源与表现 | 立绘/皮肤、音频、动画、翻译、界面部件及交互 | 提供资源和显示/操作接口；界面动作经命令校验，不直接篡改规则状态 |
| 联机与持久化 | 依赖、版本、冲突、存档/录像、重连一致性 | 固定本局内容锁；缺包/错版明确拒绝，匹配版本恢复后轨迹一致 |

旧 JS/DOM 任意修改与新原生 UI 的映射需要逐能力处理。真实客户端接入沿用平台另轨安排，
但扩展 SDK、规则执行、包生命周期、配置与显示契约属于本仓库任务，不能借另轨删除。

## 2. 最小接入边界

### 先复用包管理，再接规则执行

沿用已有命名空间、包标识、版本、依赖、逻辑/资源哈希和签名验证思路，补宿主 API 版本、入口与所需能力。
确认已有 schema 能表达的字段后再扩充，不并建第二套包仓库/依赖解算器。
具体扩展后端在兼容范围确定后用一个真实扩展比较；不把 JS、WASM、动态库或旧 VM 提前写成已定方案。

加载与调用链：**安装校验 → 解析依赖与冲突 → 合并本局目录/内容锁 → 规则执行器调用扩展 → 选择挂起/恢复 → 可见事件输出**。
仅验证 manifest 或导入成功不足以完成规则扩展。

### 本局不可变，实例可变化

内置内容继续原生预编译；启用的扩展在开局前完成注册，合并成按内容锁共享的不可变目录。
扩展拥有稳定的包/定义键，本局映射为紧凑 ID。对局中技能实例仍可获得、失去、失效，不重建或热替换本局代码。
升级/禁用影响后续对局；存量对局、存档和录像所需版本必须可保留或重新取得，不能静默加载最新版。

### 统一规则与信息边界

扩展规则使用宿主提供的查询、选择、移动牌、触发事件等接口，服从同一单写顺序、合法性校验和事务。
规则侧可读取其结算所需的权威数据；AI 与界面侧只接收合法座位视图，不能用规则接口偷渡隐藏信息。
规则随机性使用引擎 RNG，不以墙上时间、外部网络返回或不稳定遍历顺序决定结算。
资源/文件/网络等宿主能力按声明和实际授权提供，扩展不能任意改写其他包或宿主状态。

每个扩展回调需要可执行的时间/计算与内存上限。失败不能留下半次效果；
规则扩展出错时回滚该段并返回一致的故障状态，不通过静默禁用技能继续改变规则。
暂停局部状态须能编码/校验，进入快照/哈希；单靠不可序列化脚本闭包不能满足保存与回放。

### 配置、模式与 UI 也需要接入点

提供模式初始化/胜负与规则钩子、扩展配置存取、资源注册和原生 UI 部件/事件接口。
对现有修改内置函数或 DOM 的扩展，先登记所需能力，再以受支持钩子适配；不能默认当成纯贴图包。
旧扩展兼容层若需要，放在清晰的边界内验证；不能绕开宿主状态/信息约束，也不能以性能为由悄悄删功能。

## 状态与完成条件

- 逐来源功能、配置、依赖和资源清单及 G0–G5 门槛见[扩展台账](../migration/upstream-extension-reconstruction.md)。
- 只有真实扩展的规则行为、选择/恢复、安装升级回退、模式/AI/UI/联机与组合均通过对应验收，才能称该来源整包完成；卡牌数据转换、测试名或旧线能力不能代替。
- 后续报告分别写清“旧线已有”“原生接口已实现”“真实扩展已运行”“整包兼容已验收”，勿合并为笼统的“支持扩展”。
