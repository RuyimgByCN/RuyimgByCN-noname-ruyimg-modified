**先建立一次通用的包管理、规则宿主、界面和资源接口，再逐扩展改写。** 保留用户能使用的功能、配置及组合行为；旧 JS/DOM 不承诺零改动运行（2026-10-12 用户决定 D2，[ADR 0782](../adr/0782-extension-backend-and-legacy-js-scope.md)），全部按新接口重构。

## 5. 每个扩展如何判定完成

每个功能至少登记：`来源ID / 配置或入口 / 旧行为证据 / 新接口 / 依赖 / 状态 / 验证命令与日志 / 剩余问题`。
状态按 **待处理 → 部分完成 → 已重构待验收 → 验收通过** 更新，并写明是评估、单功能还是整包范围。每次更新同时填写完成日期、源码版本和证据链接；所有功能及组合/目标平台门槛通过后，才把整包标为“已完成”。旧线已有或资产复制不计原生完成。

- 规则/模式：正常与拒绝分支、目标/牌区/费用/次数/时机、嵌套响应、死亡清理、所有选择点内存及字节恢复；同命令/RNG 对照完整状态和事件，差异说明具体原因。
- 战役/档案：单局与跨关状态、奖励/购买幂等、保存中断与恢复，包升级后旧局仍可继续；原旧存档格式自动导入未因此默认纳入，但新扩展的持久化能力必须保留。
- 表现/工具：每个操作可见可用、配置保存、缺件定位、动画/音频及资源释放；原生和 web 目标分别取证，不能用旧 DOM 截图代替原生集成。
- 组合：规则覆盖冲突、主题选择、千幻/皮切/十周年、AI插件、太虚相关联动、不同来源 boss/cardpile/coin；失败信息明确且不污染其他配置/对局。
- 安装与运行：坏包、路径越界、依赖/版本不符、资源缺失、执行超额、卸载在局依赖、重复加载/更新都验证；限制服务于扩展可靠运行，不用静默丢功能通过测试。
- 定义相同的功能/配置/内容锁后，分别记录启动、规则调用、选择交互、恢复、动画帧与长局资源；此前原生内置 runner 成绩不代表扩展性能。
