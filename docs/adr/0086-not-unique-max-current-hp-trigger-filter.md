# ADR 0086：非唯一最高当前体力触发过滤器

## 背景

SP「殷积」只在技能拥有者的当前体力不为全场唯一最高时触发。若在 Rule VM 技能体内查询并跳过效果，引擎仍会把该技能记为已触发，和旧 JS 的 `filter` 语义不一致。

## 决策

追加声明式触发过滤器 `owner_is_target_not_unique_max_current_hp`。它要求技能拥有者是事件角色，并复用权威查询的存活角色、严格大于及并列判定；拥有者为全场唯一最高当前体力时不创建触发，也不运行 Rule VM。

过滤器只扩展宿主触发目录，不增加 VM 指令或查询，因此 Rule VM ABI 保持 7，且仅使用该过滤器的包仍按实际字节码能力声明最低 ABI。`TriggerFilter` 新枚举项追加在末尾，保留已有序列化序号。内容 Schema 保持 3，Rule IR 版本升至 14，清单 VM ABI 轴保持 3，引擎语义修订号升至 71。

## 后果

「殷积」在非唯一最高时强制请求二选一，在唯一最高时完全不产生触发记录。并列最高仍属于“非唯一最高”，会正常触发。
