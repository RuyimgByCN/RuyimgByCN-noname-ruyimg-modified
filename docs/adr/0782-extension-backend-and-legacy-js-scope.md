# ADR 0782：扩展执行后端与旧 JS 兼容范围（D2 / T8 定案）

日期：2026-10-12　|　状态：已采纳（用户决定 D2）
关联：[T8](../architecture/native-progress.md)、[演进提案 C1/C2](../architecture/architecture-evolution-plan.md#c1-扩展执行后端选择)、[对照草稿](notes/draft-t8-backend-comparison.md)、[扩展契约](../architecture/native-extensions.md)、[决策证据](../operations/evidence/2026-10-12-d1-d2-decisions/README.md)

## 背景

性能架构 v3.3 要求保留独立扩展：玩家可安装、启停、升级、卸载，作者可独立发布规则、武将、卡牌、模式、AI、配置、资源与界面，且规则扩展发布不重编译客户端。旧 JS 扩展零改动运行到什么程度一直未定（D2），扩展执行后端选择（T8）因此搁置。

两点事实决定取舍：

1. **旧扩展深度改写宿主。** 粗略计数（[d2-legacy-js-survey.txt](../operations/evidence/2026-10-12-d1-d2-decisions/d2-legacy-js-survey.txt)）：Liuli 29 个来源中 19 个以函数赋值覆盖 `lib.element`/`game`/`get`/`ui`，22 个直接操作 DOM。零改动运行等于在原生内核里重建旧 JS 运行时与 DOM。
2. **原生契约的三条硬约束。** 挂起状态须能编码进快照、规则随机只走引擎 RNG、AI 与界面只见合法座位视图（[扩展契约](../architecture/native-extensions.md) §2）。旧扩展依赖不可序列化的闭包续行和全局状态读写，零改动前提下三条都无法满足。

T8 对照原型（2026-10-11）以 huanle「酒尾」实测 rule-vm：数据驱动安装、字节码载体、语义与 kernel 臂等价、挂起/恢复、内容锁、超限回滚，单次触发约 85 ns（release，初步值）。WASM 候选未实测，需新增 wasmtime 依赖，浏览器端是沙箱内再嵌运行时。

## 决策

1. **旧 JS 不承诺零改动运行。** 两仓 37 个来源按功能重构（既定范围不变）。第三方扩展通过新 SDK 发布：数据走现有 npack 包数据，规则逻辑走 rule-vm 字节码。安装、启停、升级、卸载与作者独立发布能力全部保留。
2. **执行后端分层。** 内置与已转换内容继续用编译期 `HostBehavior`（候选 A）；独立发布的扩展包规则用 rule-vm（候选 B）。npack 内两种形态共存，以既有 `rule_vm_abi_version` 作版本门禁。
3. **暂不采用的方案。** QuickJS 等旧 JS 兼容层不立项，保留为演进提案 C2 候选：只有出现 37 来源之外的具体需求，且能证明确定性、权限与恢复边界时再评估。WASM 组件（候选 C）暂缓，不引入 wasmtime：出现第三方强隔离需求时，再用真实扩展实测立项。

### 备选方案（弃）

1. **QuickJS + 旧 API 垫片做零改动兼容**：须模拟 `lib/game/ui/get/_status` 全部语义与 DOM；闭包续行无法进快照，与存档/回放契约冲突；性能目标也会被旧运行时拖回。
2. **WASM 组件作唯一后端**：新增重依赖且离线依赖图中没有；浏览器嵌套沙箱未验证；D2 定案后不再需要承载任意语言的旧代码，强隔离收益暂无对应需求。
3. **维持全部编译期枚举（仅 A）**：新技能必须改引擎重编译，违反“规则扩展不重编译客户端”。

## 后果

- T8 由“待定案”转为集成任务。草稿列出的未证明项转为 T8 完成条件：engine-native 触发调度（TriggerMeta/filter/once_per_turn/阶段推进）接 rule-vm 模块；效果提交与状态机、存档快照、continuation 共存；跨进程恢复；恶意字节码拒收矩阵。完成前不得宣称“扩展规则无需重编译”已达成。
- 37 来源的迁移路线不变；台账逐来源仍分别标注新接口重构、功能缺口与实测证据，旧 JS 兼容层一项统一为“不立项”。
- 37 来源之外的社区 JS 扩展不能直接安装，需作者按新 SDK 移植。若要降低门槛，可另立转换工具任务；`legacy-analyzer` 只辅助清点，转换成功不等于功能验收。

## 验收

本 ADR 只定范围与方向，无代码改动。T8 集成按[演进提案 C1](../architecture/architecture-evolution-plan.md#c1-扩展执行后端选择)验收：无需重编译客户端即可安装含新技能/牌的包；正常与恶意输入、跨进程恢复和失败回滚均有实测。
