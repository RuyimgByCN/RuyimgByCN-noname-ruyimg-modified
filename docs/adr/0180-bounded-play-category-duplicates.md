# ADR 0180：有界出牌类别重复状态与回合伤害过滤器

## 背景

旧「狼灭」在其他角色出牌阶段结束时遍历该阶段完整用牌历史，判断是否存在两个相同逻辑类别；
在结束阶段开始时读取该角色本回合造成的伤害总量。把旧事件数组或 JavaScript 事件树带进运行时
会破坏快照、断线恢复和跨目标一致性，也会让上千技能的历史需求无界增长。

## 决策

- 追加过滤器 `owner_alive_other_play_phase_duplicate_card_category_has_hand_equip`。
  既有出牌阶段类别 `u8` 的低三位继续表示基本、锦囊、装备；第 4 位表示任一类别已经重复。
- 重复位只在加载内容实际请求该过滤器时记录。未请求它的包集合保持原状态字节和规范哈希。
- 追加过滤器 `owner_alive_other_phase_end_damage_gt_one_has_hand_equip`，复用现有回合伤害累计值，
  不建立第二份事件历史。
- 两个过滤器都要求拥有者与事件角色不同、双方存活，且拥有者至少有一张可弃手牌或装备牌。
- 「狼灭」第二段直接组合 `discard_one_hand_or_equip(self)` 与
  `deal_damage(self, event_player, 1)`。现有调度器会在弃牌 Choice 恢复并完成失牌触发后继续伤害，
  不增加技能专用效果或 continuation。

## 兼容性

Rule VM ABI 从 104 提升到 105，Engine Semantics 从 151 提升到 152。过滤器枚举只在末尾追加；
Rule IR 保持 76，内容 schema、包格式、协议和快照 schema 不变。ABI 105 主机继续加载 ABI 3–104
内容包；使用新过滤器的包必须声明 ABI 105。

## 结果

阶段历史保持常数空间，并可被后续“同一阶段是否重复使用某逻辑类别”技能复用。SP2 独占
「狼灭」定义，DIY 只通过精确依赖发布牢段煨；缺少依赖时整组拒绝，依赖齐全时扩展目录可直接
冷导入。旧 JavaScript 只作为语义合同，不进入 npack 或运行时。
