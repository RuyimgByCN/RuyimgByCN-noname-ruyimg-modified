# ADR 0171：伤害因果绑定的主动技回合内禁用

## 状态

已接受（2026-07-23）。

## 背景

旧版「骁果」可在出牌阶段重复弃置基本牌并造成一点普通伤害；只有某次伤害使目标“因此进入濒死”
时，该技能才在本回合失效。固定次数上限无法表达这项因果条件，技能名专用 Rust 分支也不利于后续
上千技能迁移。简单地在伤害请求之后查询目标是否濒死同样不可靠，因为伤害前触发和 Choice 屏障会
把预提交伤害暂停，目标也可能原本已经处于濒死状态。

## 决策

Rule VM ABI 96 增加
`deal_damage_ban_active_if_dying(source, target, amount, self_skill)`：

1. 编译器只允许它出现在主动技内，且要求技能参数为当前 `self_skill`；
2. VM 发出类型化伤害请求；宿主把技能实例 ID 附着到预提交伤害，使其跨伤害前触发与 Choice
   屏障仍保持因果关系；
3. 伤害继续使用普通无牌、普通属性伤害的修正和提交路径；
4. 只有该次提交实际发出目标的 `EnteredDying` 事件时，才设置技能实例的
   `active_turn_banned`；
5. 命令层仅拒绝该实例的主动发动，不改变其触发技或修改器索引；下一名角色的回合开始时统一清除
   所有回合内主动禁用状态。

同一 ABI 追加主动选牌过滤器 `card_basic`，按有效牌类别筛选手牌。archive 中的 JavaScript
只提供语义合同，不进入 DSL 包或运行时。

## 后果

- 「骁果」没有虚假的大次数上限；未造成濒死时可继续发动。
- 目标原本已濒死、伤害被防止或伤害降为零时均不会禁用技能。
- 即使目标随后被【桃】救回，首次进入濒死的事实仍会使技能在当前回合失效。
- 伤害修改器、濒死救援、序列化续体和确定性哈希只保留一套通用实现。
- ABI 95 主机拒绝 ABI 96 包；ABI 96 主机继续加载旧的加法式内容包。
