# ADR 0528：ABI 615 归档扩展“玩点论杀”杨仪与调兵遣将

旧 JavaScript 仅作语义证据，不进入 npack 或运行时。归档扩展“玩点论杀”的杨仪
（`wdb_yangyi`，3210186788）以 3 体力、蜀势力发布完整武将。

「筹度」（`choudu`，4166492495）出牌阶段限一次，弃置一张手牌或装备牌，选择一名存活角色，
令其使用虚拟【调兵遣将】。成本、目标和技能状态在 Choice 恢复时重新校验；虚拟牌复用普通
【调兵遣将】结算，不执行旧 JavaScript。

「立断」（`liduan`，2934618094）在其他角色于其回合外恰好获得一张装备牌到手牌、该装备槽可用
且该牌可正常使用时可发动。获得者可交给杨仪一张手牌；取消则必须通过普通装备使用管线立即使用
刚获得的装备。触发和 Choice 均绑定该实体装备牌，避免同批移动或后续移牌造成误结算。

【调兵遣将】（`diaobingqianjiang`，2631024706）是全体普通锦囊。使用者先摸一张牌，再亮出牌堆
顶 `ceil(存活角色数 / 2)` 张牌。声明时有手牌的其他角色与使用者按座次成为目标；每个目标独立
经过标准【无懈可击】奇偶响应窗口，未被抵消且仍有手牌的目标可用一张手牌替换一张亮出牌。
全部目标结束后，使用者必须选择至少一张剩余亮出牌，并按选择顺序置于牌堆顶（第一张为牌堆顶），
其余牌进入弃牌堆。所有中间牌均位于公开处理区，续体和 Choice 可序列化、恢复并重新校验。

ABI 615 新增 `resolve_wdb_yangyi(player, target, card, action)`、立断精确移牌过滤器、
`diaobingqianjiang` 卡牌种类和可恢复结算续体。实现复用现有全体锦囊逐目标队列、标准无懈窗口、
实体牌移动、装备使用、公开处理区和牌堆顶移动，不引入第二套扩展加载或牌处理框架。

验收：杨仪/调兵遣将 Golden 6/6、content-compiler 512/512、Rule VM 10/10 与 5/5、
engine-api 4/4、engine-core lib 55/55、conformance 8/8，以及包含本包的 27 个扩展空 store 冷导入
均通过。`official/wandianlunsha@0.1.0` 累积为 ABI 615、8 名武将、18 项技能、15 个模块、
12 个触发、3 项主动技、11 项修正器、2 项视为技、2 张卡和 10 项资源，logic hash 为
`1ed3d8cd3d32aefcde111482e1a943957eada920823695cac9b79c8972b3538c`；源码目录与
`extensions/wandianlunsha` 四份 npack SHA-256 均为
`a342f061afeb0ed84db21d0fb43eab3f0f452121b4daf140c94a731185d495fe`。归档、源码目录和
extensions 三份杨仪立绘 SHA-256 均为
`3cc5fbad3a8af238948538318a91e499b3a7850d974878f21c89c0b362668637`，三份【调兵遣将】卡图
SHA-256 均为 `4048c9dcbab986ea8279d39357fcb269d3b00b458e0f0d1c86931c58d006a83c`。

编译产物不得无限累积。按架构计划 §37.10，本批所有编译、测试、打包和冷导入结束后，只清理
Rust/Cargo 编译缓存：外部 `/private/tmp/noname-next-cargo-target` 删除 8,849 个文件（Cargo
报告 5.8 GiB），工作区 `target/` 原本不存在；验收时两处编译目录均不存在。`.npack`、
`extensions/`、立绘、卡图、许可证和迁移源码均为发布物，明确保留且清理后哈希不变。归档扩展
的其他内容继续按同一流程迁移，本 ADR 不代表 `/archive/upstream/noname` 全量完成。
