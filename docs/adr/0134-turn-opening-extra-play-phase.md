# ADR 0134：回合开端额外出牌阶段队列

## 决策

Rule VM ABI 44 增加：

```text
queue_opening_extra_play_phase(player)
```

换人时引擎不再直接从上一名角色的结束阶段跳到下一名角色的准备阶段，而是对需要 ABI 44 的内容
先进入不可操作的 `Idle` 回合开始窗口并发布 `TurnBegan`。所有 `phase_begin` 技能在该事件上按既有
触发顺序结算；锁定技可向当前玩家的固定容量队列加入额外出牌阶段。触发队列完成后，引擎进入首个
额外出牌阶段；全部额外阶段完成后才进入准备阶段。队列最多八段，技能不能修改或持有阶段数组。

每次进入新的出牌阶段都会清空当前阶段的【杀】额度、主动技次数与阶段牌史；回合范围的【杀】总计
继续累积。因此额外出牌阶段和正常出牌阶段各有独立基础额度，而依赖整回合历史的技能仍看到准确
总数。显式 `TurnBegan` 标记还避免从额外阶段返回准备阶段时再次触发回合开始。

## 原因

旧「当先」用 `trigger.phaseList.splice(...)` 修改可变 JavaScript 阶段数组。照搬该结构会让技能
持有引擎控制流、难以恢复 Choice、重放和跨端哈希，也会把阶段次数与回合次数混为一谈。类型化、
有界的阶段意图把“请求额外阶段”和“如何推进回合”分离，之后同类技能可以复用同一生命周期，
无需新增技能 ID 分支。

ABI 44 生命周期只在加载对应内容时启用；旧包继续使用原来的结束阶段到准备阶段转换，零状态向量
和既有哈希不变。旧 JavaScript 仅保留为语义证据，运行时不会解释或执行。
