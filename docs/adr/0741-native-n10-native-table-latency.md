# ADR 0741：N10 自动化文本宿主示例与 submit 延迟

日期：2026-09-16
状态：已实施（engine-native/examples/n10_table.rs）
关联：[0732](0732-native-n10-ai-session-bounded-pool.md)、[0731](0731-native-n10-choice-event-visibility.md)、进度文档 N10

## 独立复核更正（2026-09-22）

n10_table 的 Instant 在视图读取和策略计算之后创建，只包围 submit；本轮 10 局 9488 样本、P50/P95=2750/3917 ns。
这不是原稿所称“视图→策略→命令”的端到端时间，更不是系统输入到帧提交延迟。
示例没有 GPU/窗口，seat_command 参数仍为 &Engine；现有策略使用视图不等于类型上无法访问权威状态。
命令配额不是 AI 计算池，且私有事件泄露仍存在，不能由此关闭 N10。

当前反例、优先级与证据见 [进度主稿](../architecture/native-progress.md)。以下保留当批设计/记录，不作为当前完整验收结论。

## 背景与决定

N10 尾项「原生牌桌与输入延迟」：需要一个**只用可见性投影**驱动的完整牌桌
实现，验证 AI 会话信息隔离在端到端场景成立，并给出原生环境下的输入链路
延迟基线。

### 实现（`examples/n10_table.rs`）

- 全座位自动化：每个座位一个 `Engine::ai_session(seat)`——策略仅读
  `view()`（自己的手牌/公开区/回合）与 `choice()`（Own 完整选项），
  **权威状态不可达**（类型系统约束）；
- 有界计算池：`set_seat_quota(Some(64))`——每座位每轮至多 64 条命令；
- 输入延迟定义与测量：视图读取 → 策略决策 → 命令提交 的端到端纳秒
  （原生输入链路下限，无网络/渲染开销）；逐命令采样；
- 拒绝后强制推进（防原地重试死循环）；事件流按局读取一次
  （避免逐命令全量克隆的 O(n²)）。

### 结果（5 人身份局 × 10，seed 7000 起，release）

| 项 | 值 |
|---|---|
| 终局 | 10/10 达阵营终局（全部 Rebels） |
| 命令总量 | 10,360 条 |
| 输入延迟 | P50 = 2000ns，P95 = 2500ns，P99 = 3167ns |
| 有界池 | 每座位每轮 64 条，无死锁（拒绝后强制推进） |

原始输出：[n10_table.log](../operations/evidence/2026-09-16-native-n09/n10_table.log)。

## 影响

- N10「原生牌桌与输入延迟」闭合：信息隔离端到端成立（AI 只读视图即可
  完成整局），输入链路延迟有基线数据。
- N10 全部尾项清零；剩余为 N12 旧线对照/真机验证（需专门批次）、
  N11 完整模式/内容。
