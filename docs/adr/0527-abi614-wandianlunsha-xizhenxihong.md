# ADR 0527：ABI 614 归档扩展“玩点论杀”习珍习宏

旧 JavaScript 仅作语义证据，不进入 npack 或运行时。归档扩展“玩点论杀”的习珍习宏
（`wdb_xizhenxihong`，2196609533）以 4 体力、蜀势力发布完整武将。

「负仇」（`fuchou`，3890431595）在习珍习宏成为【杀】目标且其有手牌或装备牌时，可交给
【杀】来源一张牌并取消该目标；来源按首次出现顺序去重记录。每个全局回合结束后清空记录并按
原顺序处理仍存活的来源：习珍习宏先摸一张牌，再可无距离限制地对该来源使用一张实体或转化
【杀】，拒绝或没有合法【杀】则失去 1 点体力，随后继续处理下一来源。旧技能描述另称“本回合
到该来源的距离视为 1”，但旧 JavaScript 没有对应修正器或状态写入，故按实际可执行语义不实现。

「噤言」（`jinyan`，3563375486）在拥有者体力不大于 2 时，禁止黑色锦囊按原逻辑牌名使用或
响应；拥有者仍可从手牌选择一张黑色锦囊，经本技能视为【杀】使用或打出。响应检查区分实体牌
与转化后的逻辑牌名，因此黑色【无懈可击】不能按【无懈可击】响应，却能按【杀】响应。当前卡池
没有可用于救援的黑色锦囊，且转化结果【杀】也不可救援，无需虚构额外救援分支。

ABI 614 新增 `resolve_wdb_xizhenxihong(player, target, card, action)`、可携带牌分类选择器的
响应禁用修正器、`owner_hp_le_two_black_trick` 视为牌过滤器、负仇触发过滤器，以及可序列化的
`ContinueWdbFuchou` 内部续体。实现复用既有实体牌移动、摸牌、失去体力、实体/转化【杀】选择
与无距离/次数限制的【杀】结算管线，不引入第二套牌处理框架。

验收：习珍习宏 Golden 6/6、content-compiler 511/511、Rule VM 10/10、engine-api 5/5、
engine-core lib 55/55、conformance 8/8，以及包含本包的 27 个扩展空 store 冷导入均通过。
`official/wandianlunsha@0.1.0` 累积为 ABI 614、7 名武将、16 项技能、13 个模块、11 个触发、
2 项主动技、11 项修正器、2 项视为技、1 张卡和 8 项资源，logic hash 为
`a91466b454c2f782b3b4537b7ae1a6f16c4b43420090758ea8a1fee212f9a720`；源码目录与
`extensions/wandianlunsha` 四份 npack SHA-256 均为
`3336b3749df02d8227a18c4d61f5c5ebf07bf48c063e0d92c5b6436f87084311`。归档、源码目录和
extensions 三份习珍习宏立绘 SHA-256 均为
`453044c6f90f55f6909b11033d1df17ec8a9a0d8f950073bbe211e37d0fbd0bb`。

编译产物不得无限累积。按架构计划 §37.10，本批所有编译、测试、打包和冷导入结束后，仅清理
Rust/Cargo 编译缓存：外部 `/private/tmp/noname-next-cargo-target` 删除 8,388 个文件（Cargo
报告 5.5 GiB），工作区 `target/` 原本不存在；验收时两处编译目录均不存在。`.npack`、
`extensions/`、立绘、许可证和迁移源码均为发布物，明确保留且清理后哈希不变。归档扩展的其他
内容继续按同一流程迁移，本 ADR 不代表 `/archive/upstream/noname` 全量完成。
