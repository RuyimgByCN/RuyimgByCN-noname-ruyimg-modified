# ADR 0147：暂停中的用牌者转移与伤害提交前减值

## 决策

旧版 JavaScript 只作为技能语义证据，不进入内容包，也不在运行时执行。新增
`choose_card_user_or_add_target(player, card)` 处理暂停中的单目标【杀】或普通锦囊：技能拥有者先从
该牌仍合法的额外目标中选择一名角色，该角色再选择交出一张当前手牌并成为该牌的新使用者，或不交牌
而成为额外目标。技能的阶段计数仅在首个目标选择通过原子校验后写入；只有确认可选触发但已无合法
目标时不会错误消耗次数，每次真实阶段迁移仍由通用阶段机清零。

交牌通过语义化 `GiveCards` 进入普通移动触发队列，用牌者转移作为队列尾部的内部提交，保证嵌套移动
触发全部完成后才修改暂停续体。【杀】续体和整次【杀】记录、普通锦囊的无懈续体及独立目标队列都会
同步替换来源，并发出 `CardUserChanged` 领域事件。交牌前校验候选资格，交牌后只复核新使用者存活、
与原目标不同及暂停上下文；不再把已经交出最后手牌的新使用者误当作火攻等牌的目标重新解释。
不交牌分支复用既有通用追加目标提交和 `CardTargetAdded` 事件。

新增 `choose_discard_equipment_reduce_current_damage(player)` 绑定引擎分配的 pre-damage ID。候选为拥有者
手牌区或装备区内可弃置且有效逻辑类别为装备的实体牌；选择恢复时重新校验来源技能、伤害 ID 与牌区。
支付弃置后把该次已应用静态修正的最终伤害减一；减至零时走统一伤害防止记录。元素连环使用的
`base_amount` 不受目标侧此次减值影响。性别和候选判断由声明式过滤器完成，核心不识别「谮毁」、
「骄矜」、孙鲁班或包。

## 兼容性

`DomainEvent`、`EffectRequest`、`ContinuationKind`、触发过滤器、Rule IR 语句和 VM host effect tag
均只在末尾追加，保留已有序列化序号。Rule VM ABI 升至 57，Rule IR 升至 68，Engine Semantics
升至 143。旧包不获得新能力，仍按其原最低 ABI 加载。
