# ADR 0154：绑定伤害的强制防止/增伤分支

## 决策

Rule VM ABI 64 增加
`choose_prevent_damage_or_lose_max_hp_increase_damage(player, amount)`，只允许
`damage_before` 触发器调用。引擎把当前待结算伤害 ID 与来源技能写入效果请求，并向伤害来源开放
不可取消的精确二选一：防止该伤害，或先失去 1 点体力上限，再令同一次伤害增加 `amount`。

增伤分支把后续操作保存为可序列化 continuation。体力上限变化及其嵌套触发全部结算后，continuation
重新验证伤害 ID 和来源，再同步增加待结算伤害的当前值及属性传导基数。选择恢复会验证观察者、
选项、伤害上下文和来源；取消、伪造选项或陈旧伤害上下文均原子拒绝。

## 原因

旧实现的 `await player.loseMaxHp(); trigger.num += 2` 有明确的异步顺序和事件绑定。普通 DSL
`choose` 允许取消，也没有安全引用当前待结算伤害的能力；执行旧 JavaScript 则违反确定性内容边界。
显式通用效果保留顺序、回放和 Native/WASM 一致性，又不让核心识别具体武将或技能名称。

## 边界

核心只识别“绑定伤害的来源、强制防止/失去体力上限后增伤”这一通用规则结构，不识别「暴拳」、
井之原真人或 KEY 包。Golden 必须覆盖强制选择、两个分支、来源门控、取消/伪造选择原子拒绝，
以及包内武将与技能闭包。旧 JavaScript 只作语义证据，不进入包或运行时。
