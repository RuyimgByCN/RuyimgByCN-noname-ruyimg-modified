# ADR 0785：原生 GPU 牌桌原型（PA11 草案）

日期：2026-10-26　|　状态：**草案（原型未落地，不构成投入决定）**
关联：[性能架构 §8](../../noname-performance-architecture.md)、[台帐 PA11](../architecture/native-remaining-ledger.md#pa01pa12-性能架构调整2026-10-26)、[PA08 证据族](../operations/evidence/)

## 背景

当前表现层为 Vue + DOM。性能架构 §8 设想保留式原生牌桌（wgpu）以换取确定性帧预算与复杂特效空间。PA08 扩面（2026-10-26）实测了 DOM 方案的真实余量，这是投入裁决的基线：

| 场景（DOM 现状实测） | 关键指标 | 余量结论 |
|---|---|---|
| Chrome/Firefox 120Hz 整局 | 帧 p99 ≤10.3ms、掉帧 0.035% | 预算 8.3ms 内极充裕 |
| WKWebView/iOS 模拟器 60Hz 整局 | 帧 p99 ≤32ms、Long Task 0 | 同 |
| 满手牌 30 张 | view_json+parse+adapt p95 ≤1ms | 序列化非瓶颈 |
| 32 分钟连续 16.6 局 | Long Task 0、内存平坦 | 无衰退 |
| vue_patch（DOM 刷新） | p50 1-2ms | 预算内 |

**结论性判断（草案）**：DOM 方案在全部已测场景远未逼近预算——PA11 的性能动机当前不成立；剩余动机只有「复杂特效/保留式动画的表达力」，属产品诉求而非性能诉求。

## 决策（草案）

1. 原型若做，范围收敛为一个牌桌场景的 wgpu 对照（等价素材、同设备）：帧间隔、点击到出帧、功耗三指标对照 DOM 版；不移植规则/交互全量。
2. 投入与否由用户拍板；拍板前不立项。**性能架构 §8 的 GPU 牌桌不应作为性能债务排期**（依据上表）。
3. 若未来真实需求出现（如大特效、回放剧场化），先以本 ADR 附带的对照口径立项复测。

## 状态

原型未开始；本草案先行锁定「DOM 余量充足」的事实基线与对照口径。
