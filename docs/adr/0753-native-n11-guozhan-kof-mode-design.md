# ADR 0753：N11 大模式设计——国战与 KOF 的引擎级实现路径

日期：2026-09-16
状态：设计定稿（实现分批推进）
关联：[0746](0746-native-n11-active-skill-command.md)、[0752](0752-native-qixi-paoxiao.md)、进度文档 N11、性能架构 v3.2 平台阶段

## 背景

N11「完整模式/内容」要求引擎支持身份局之外的大模式。本批给出
**国战**与 **KOF** 的引擎级设计，明确各自对现有内核的增量需求与
里程碑切分，作为后续实现批次的依据。

## 一、KOF（1v1 轮换竞技）设计

### 形态

- 座位 2 名，各持有 N 名武将（官方 1v1 为 4 将轮换）；
- 单局败者淘汰替补，先让对方无将可用者获胜；
- 单局内规则与现行 Prototype 2 人局一致（杀/锦囊/装备/濒死全复用）。

### 引擎增量

1. **多局会话层**（宿主侧，非内核）：KOF 是「多局 + 淘汰」的会话状态机，
   内核单局（Engine）不感知轮换。宿主按局终局（Winner::Player）轮换武将、
   以 NGSA 存档每局终态（存档链路已就位，ADR 0733/0735）；
2. **武将预选**：开局授予（`debug_grant_general` 已具备，ADR 0724）；
3. **无需新的 GameMode 变体**：单局用 Prototype 2 人局表达；
   KOF 会话层登记胜负序列即可。

### 里程碑

- M1：Prototype 2 人局纯命令终局回归（已有能力，补一条显式回归）；
- M2：宿主 KOF 会话（轮换/胜负序列/存档链）；
- M3：KOF 专用统计（局数/将池消耗）。

## 二、国战模式设计

### 形态

- 座位 2–8 名，每名玩家持有**两个武将**（主将/副将），体力为两将体力上限
  之和减 1；
- 身份（势力）暗置，首次发动技能/成为目标时点亮（明置）；
- 势力胜利：场上仅剩同一势力（或与珠联璧合规则相关的组合）。

### 引擎增量（按依赖排序）

1. **双将数据模型**：`PlayerState` 扩展 `generals: [GeneralId; 2]` 与
   `general_revealed: [bool; 2]`（状态编码变化 → 版本递增 + golden 重录）；
2. **势力模型**：`Faction` 枚举（魏/蜀/吴/群）与武将→势力映射
   （`STANDARD_GENERALS` 扩展为带势力字段）；
3. **明置规则机器**：首次亮将时点（受击/发动技能/回合开始）的触发与询问；
4. **势力胜负判定**：`DeathMachine` 的胜负分支扩展（唯一势力存活判定）；
5. **暗置技能资格**：明置前技能不可发动/触发（`has_skill` 扩展明置检查）。

### 里程碑

- M1：数据模型 + 编码/存档/哈希同步（一次版本递增）；
- M2：势力与明置规则 + 触发门控；
- M3：势力胜负 + 回归矩阵（4/6/8 人国战局）；
- M4：珠联璧合等进阶规则（挂账）。

### 依赖与风险

- 双将模型触碰 `PlayerState`/快照/存档/哈希四处，是六处同步模式的放大版；
- 明置时点的规则细节需对照官方规则书与旧线实现（旧线对照依赖 N12
  驱动器闭环，可并行推进）。

## 三、优先级建议

KOF M1–M2 依赖少（复用存档与身份局），建议先于国战实施；
国战 M1（数据模型）可与 KOF 并行。两者均不阻塞当前
N12 真机验证与旧线驱动器（需会话外环境）。
