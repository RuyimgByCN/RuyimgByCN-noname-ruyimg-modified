# ADR 0109：通用牌目标上限与整局一次触发

## 决策

DSL 新增 `card_target_limit(selector) add N` 修正器。它只改变可独立选择、逐目标结算的牌的最大
目标数：当前覆盖【过河拆桥】【顺手牵羊】【火攻】【决斗】和【铁索连环】；全体锦囊及
【借刀杀人】这类成对目标结构不套用该上限。实体牌和无来源 `view_as` 共用查询入口，合法动作
生成、命令校验与客户端候选均读取同一结果。

单目标普通锦囊增加目标后，每名目标依声明顺序拥有独立的【无懈可击】窗口并独立结算。
`IndependentTrickQueue` continuation 保存牌、来源、目标序列与当前位置；取牌、展示、弃牌、决斗、
伤害及濒死中断均携带该尾队列，完成当前目标后才推进下一名目标。

触发目录新增 `owner_is_event_player_no_enabled_equip_slot_once_per_game`。`SkillInstance` 追加带
反序列化默认值的 `lifetime_fire_count`，触发规划同时计算同一批事件中已计划的次数，避免一次
废除五个栏位产生五次触发；计数进入 canonical state hash，且整局不重置。`add_skill` 同时改为按
稳定定义 ID 幂等，重复获得同一技能不产生第二个实例。

该能力要求 Rule VM ABI 19、Rule IR 30、引擎语义修订 105。ABI 19 主机继续按加法兼容规则加载
ABI 3–18 包；内容 Schema 与网络协议 5 不变。新枚举项和 continuation tag 34 均追加在末尾，旧
快照中的技能实例把整局计数缺省为零。

## 理由

“额外增加目标”和“首次满足条件”是大量旧技能共享的规则表面，不应由某个技能 ID 或旧
JavaScript 回调实现。统一查询、队列和生命周期计数后，扩展只声明选择器、增量与触发效果，
物理牌和无来源转化牌自然复用同一权威管线。
