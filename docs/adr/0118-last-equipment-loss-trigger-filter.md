# ADR 0118：类型化失去最后装备过滤器

## 背景

旧「典封」监听多种牌移动完成事件，再用 `event.getl(current).es` 找出本次确实失去装备牌、且
结算后装备区为空的每名角色。只检查“装备区当前为空”会让原本就没有装备的角色因手牌、判定牌
或扩展牌移动而误触发；只检查“从装备区离开”又会在仍有其他装备时提前触发。

## 决策

新增通用过滤器 `owner_alive_event_player_from_equip_empty`。它只接受 `cards_moved` 事件，并要求：

- 技能拥有者和事件角色均存活；
- 本事件移动数量大于零，来源区域为事件角色的装备区；
- 事件处理后的装备区为空。

权威牌移动管线按来源区域与拥有者发出独立 `CardsMoved` 事件，因此旧 `loseAsync` 同时影响多名
角色时，每名失去最后装备的角色仍会依座次形成独立触发；无需把旧 JavaScript 的事件回溯对象
带入运行时。`sixiang:stddianfeng` 使用该过滤器可选触发并令技能拥有者摸一张牌。旧 JS 的音频、
日志目标和 AI 频繁发动提示不进入权威规则。

标吕范还依赖尚未重写的 `shiji:mbdiaodu`，所以本次只发布技能定义，不提前发布武将。

## 版本

该能力要求 Rule VM ABI 28、Rule IR 39、引擎语义修订 114。ABI 28 主机继续按加法兼容规则
加载 ABI 3–27 内容包。
