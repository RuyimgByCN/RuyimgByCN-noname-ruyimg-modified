# ADR 0188：较多手牌目标的延迟重复选择

## 状态

已接受。

## 背景

旧 COLLAB「子鼠」在出牌阶段先强制选择一名手牌数更多的其他角色，取得其一张手牌；此后反复
比较全场手牌数，直到技能拥有者并列最多，或拥有者主动停止。旧实现依赖动态 `filterTarget`、
`choosePlayerCard`、事件步骤和 `goto` 循环。

新运行时不能执行旧 JavaScript，也不能让内容脚本持有可变事件对象。已有通用取牌效果允许从
手牌或装备区取一张牌，且没有表达“首次强制、后续可选、每次移动结算后重新比较”的状态机，
直接复用会扩大可选区域并改变时序。

## 决策

增加主动目标约束 `hand_gt_owner`，在主动命令提交和 Choice 恢复时都要求目标存活、不是拥有者，
且目标当前手牌数严格大于拥有者。

增加 staged effect `take_target_hand_then_repeat_until_max`：

- 首次使用主动技能时必须提供一个满足约束的目标；
- 牌 Choice 仅暴露该目标当前手牌，且必须选择一张；
- 牌移动完成后，把继续判断放入 deferred tail，等待移动产生的嵌套触发全部结算；
- 若拥有者手牌数已并列全场最多则结束；
- 否则提供可取消的目标 Choice，只列出当前手牌数仍更多的其他角色；
- 选择目标后再次提供不可取消的单张手牌 Choice，完成后重复同一流程。

所有 Choice 都绑定观察者，并在恢复时重新验证目标、实体牌所有权和区域；非法或过期选择不会
产生部分状态修改。

## 版本与兼容性

- Rule VM ABI：112 → 113；
- Engine Semantics：159 → 160；
- Rule IR：76 → 77；
- 新增 HOST_EFFECT 129；
- `EffectRequest` 尾部追加公开取牌请求与内部继续请求；
- `ContinuationKind` 尾部追加稳定标签 89。

内容 schema、包格式、协议、回放和快照 schema 不变。只有使用新目标约束或效果的内容包声明
ABI 113；已有枚举值和序列化标签不重排。

## 后果

同类“满足动态数量条件后逐次取牌，结算后决定是否继续”的技能可以复用确定性状态机，不需要
执行旧事件脚本。取牌区域、首次与后续是否可取消、嵌套触发时序及恢复校验均成为跨 Native、
WASM、录像和 AI 一致的宿主契约。
