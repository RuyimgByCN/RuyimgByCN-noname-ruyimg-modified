# ADR 0133：当前【杀】次数退款凭据

## 决策

Rule VM ABI 43 增加：

```text
owner_alive_play_phase_sha_user_has_discardable_hand_equip
choose_discard_one_for_sha_refund_and_draw_if_red(player, sha_user, card)
```

主动【杀】进入 `CardUsed` 触发前，若加载内容需要 ABI 43，引擎在既有单目标或多目标【杀】
续体的响应标志中同时保存“本次是否实际计入出牌阶段次数”。组合效果在开始时重新枚举可弃的
手牌/装备牌，并在选择续体中再次校验成本；只有弃牌成功后，才把内部退款/摸牌效果排进同一 FIFO
效果队列。若多个预先规划的触发依次结算、后触发者此时已无可弃牌，组合效果直接无事发生，不会
出现未支付成本却获得收益。退款阶段重新校验保存的来源玩家和
实体牌，只在该位已设置且尚未退款时把 `SHA_PLAYED` 减一，并在同一续体中设置退款位。多名技能
拥有者对同一张【杀】发动时因此最多退款一次；原本忽略次数的虚拟【杀】不会误减此前的计数。

弃牌成本和收益由专用可恢复选择屏障绑定；红色判断使用出牌者视角下的有效花色，摸牌仍携带
来源技能。旧 JavaScript 的
`trigger.addCount` 和统计表原地修改不会进入运行时。

## 原因

只读取全局 `SHA_PLAYED > 0` 无法区分“当前【杀】计数”与“此前【杀】留下的计数”，也无法防止
多个「龙吟」重复递减。为每个技能保存临时标记又会把同一张牌的事实复制到上千技能实例。把三个
固定 bit（可响应、已计数、已退款）放在本来就必须保存的当前【杀】续体中，状态大小保持常数，
并覆盖普通、视为、多目标与不计次数的主动【杀】。

该凭据只在 ABI 43 包加载时写入；旧内容的续体载荷和既有状态哈希保持不变。
