# ADR 0006: ContentLock 加载与模块命名空间

## 决策

- 扩展包由 `PackageStore` 安装并通过精确版本依赖形成 `ContentLock`。
- 引擎只从规范化锁文件加载。普通依赖仍然依赖优先；精确版本互相引用形成的强连通组随完整
  `ContentLock` 原子激活，组内按 `namespace/package_id` 排序，组外仍保持依赖优先。
- 包内 VM 模块名在运行时映射为 `namespace/package_id::module`，避免不同扩展同名冲突。
- 对局开始后固定锁哈希，不在运行中的对局热更新。

## 影响

模块键进入确定性状态，因此本 ADR 同步更新 StartGame 和整局 Golden 哈希。旧 npack
仍可读取；新增依赖、翻译和资源字段均为可选默认字段。

互相依赖不放宽完整性校验：组内每个包仍必须存在，版本和可选逻辑哈希必须精确匹配。该规则
允许上游武将包按原归属引用另一包的稳定技能 ID，而无需搬移或复制技能定义；单包缺失时整个
激活事务失败。
