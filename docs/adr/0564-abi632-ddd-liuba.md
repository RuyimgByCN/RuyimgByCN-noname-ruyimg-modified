# ADR 0564：ABI 632 3D精选刘巴【丰政/玉律】

本批按武将闭包发布刘巴（`ddd_liuba`，346974214）与【丰政】（`dddfengzheng`，986583704）、
【玉律】（`dddyulv`，694263366）。旧 JavaScript 只作语义证据，不进入 npack 或运行时。

【丰政】为每名角色提供自己的不可获得全局技能实例：其出牌阶段限一次，将任意张点数和恰为
13 的手牌作为完整【无中生有】使用。全局入口在开局安装，也在对局中途获得【丰政】时由共享
`AddSkill` 管线补装；没有存活且技能有效的【丰政】拥有者时入口不可用。每轮首次实际阶段开始，
刘巴可按上一轮不同使用者人数取得等量牌堆顶牌，反复选择非空子集与获得者，全部分配完成后
才统一移动；任一角色获得超过两张，嵌套获得事件完成后刘巴失去【丰政】。

【玉律】开局先摸一张，再将一张手牌公开置于独立技能牌堆。任意一次实体移牌批次令与“玉律”
物理点数相同的牌进入弃牌堆时，每批只触发一次，刘巴令当前回合角色摸一张或弃置一张手牌/
装备牌；本回合第二次发动后，刘巴用一张手牌与“玉律”交换，没有手牌则先摸一张再交换。

ABI 632 增加 `resolve_ddd_liuba(player,actor,action)`、
`owner_alive_ddd_fengzheng_round_pending`、`owner_alive_ddd_yulv_discard_matches`，以及点数和为 13
的多手牌主动选择契约。实现复用普通【无中生有】结算、实体移牌、公开技能牌堆、回合/轮次技能
计数和可恢复 Custom Choice，不引入第二套扩展加载或 JavaScript 执行器。

验收：【丰政/玉律】Golden 3/3、content-compiler 522/522、engine-api 4/4、engine-core lib 55/55、
Rule VM 单元 10/10 与集成 5/5、conformance 8/8、31 个扩展空 store 冷导入均通过；内容锁为
`69348c308d4669260083f45dab366104990e17fac6cfe79a00cac39851e7ed14`。

`official/ddd@0.1.0` 更新为 ABI 632，累计含 16 名武将、35 项技能、46 个模块、42 个触发、
4 项主动规则、5 项视为规则、4 项修正器和 16 项立绘资源；logic hash 为
`eb56ae010cb69c59a513179e21d4593efb916f3b9f5723b7afa161a007e3a0e0`，asset hash 为
`1179272ef064023ece0ff204f2973764ca79aa28712ac60ef75df15f8b1a655d`。源码目录与
`extensions/ddd` 四份 npack SHA-256 均为
`be51394f32b63e040ebc9d29283c2040ab1151d870a6f5ab42f47080b16d2b61`；两份刘巴立绘 SHA-256
均为 `64dbaea7f87c75b1ce73267d3df533a3c96efb13bd8a43f00d5959c88d80145c`。

编译产物已按架构计划 §37.10 在本批门禁结束后清理：外部共享目录删除 5,050 个文件（Cargo
统计 3.3 GiB），工作区 `target/` 原本为空，冷导入临时库同时删除；验收时三处目录均不存在。
`.npack`、扩展、立绘、许可证、源码和文档属于交付物并保留，清理后上述交付哈希不变。本 ADR
只证明 3D精选第十六个武将闭包，不代表整个扩展迁移完成。
