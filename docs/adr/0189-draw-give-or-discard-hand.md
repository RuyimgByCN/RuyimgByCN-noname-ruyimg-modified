# ADR 0189：摸牌后的交牌或弃牌分段选择

## 状态

已接受。

## 背景

旧 MOBILE「宵赂」在出牌阶段限一次：先摸两张牌；若随后手牌不足两张，弃置当前手牌；否则
选择把两张手牌交给一名其他角色，或弃置两张手牌。旧实现用 JavaScript 事件步骤串联摸牌、
分支、目标和卡牌选择。

新运行时不执行旧 JavaScript，也不能在内容脚本里保存可变事件对象。把“摸牌”和“后续选择”
拆成普通相邻效果会让摸牌产生的嵌套触发与后续 Choice 顺序不明确，并且无法在录像恢复或
网络提交时重新验证目标和实体牌状态。

## 决策

增加仅限主动技能的 staged effect：
`draw_then_choose_give_or_discard_hand(player, draw_count, payment_count)`。

- 首先执行摸牌，再把后续阶段放入 deferred tail，等待该批牌移动及嵌套触发完整结束；
- 手牌不足支付数量时，弃置所有当前可弃置手牌；
- 手牌足够时，强制选择交牌或弃牌；没有其他存活角色时只允许弃牌；
- 交牌分支依次选择一名其他存活角色和准确数量的本人手牌；
- 弃牌分支选择支付数量与当前可弃置手牌数的较小值；
- 每个 Choice 恢复点都重新验证观察者、技能实例、角色存活、目标合法、实体牌所有权、手牌区
  和选择去重，任何过期提交都不会产生部分修改。

分支状态只保存在稳定 continuation payload 中，不保存 JavaScript 闭包或旧事件对象。

## 版本与兼容性

- Rule VM ABI：115 → 116；
- Engine Semantics：160 → 161；
- Rule IR：77 → 78；
- 新增 HOST_EFFECT 131；
- `StmtIr` 与 `EffectRequest` 尾部追加新变体；
- `ContinuationKind` 尾部追加稳定标签 91。

内容 schema、包格式、协议、回放和快照 schema 不变。只有使用新效果的内容包声明 ABI 116；
已有枚举值与序列化标签不重排。

## 后果

同类“先完成一个带嵌套触发的动作，再进行多阶段卡牌支付”的主动技能可以复用确定性宿主
状态机。内容仍是简短声明式规则，旧 JavaScript 只保留为迁移语义参考；Native、WASM、录像、
断线恢复和 AI 观察到相同的选择顺序与校验结果。
