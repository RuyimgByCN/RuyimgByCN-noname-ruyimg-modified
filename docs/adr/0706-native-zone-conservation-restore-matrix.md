## 背景

第八批后的独立复核以定向探针复现了四处缺口（N01–N04），并把
「快照结构校验 + 各机器暂停点恢复矩阵」（N05）列为阶段 2 验收项：

- **N01**：AOE 目标被无懈抵消后，`NullifyWindowMachine` 抵消弃牌与
  `AoeResolveMachine` 收尾弃牌都执行——同一南蛮实体牌进弃牌堆两次。
- **N02**：判定阶段中拥有者死亡（如闪电命中），待判队列里的延时锦囊
  在阶段开始时已从判定区取出，机器直接结束导致牌凭空消失。
- **N03**：闪电未命中转移直接 `push` 下家判定区，未复用同名牌限制——
  下家已有闪电时会形成同名牌堆叠。
- **N04**：快照身份列表可被清空/改组仍恢复成功；胜负与模式关系、
  OptionalGate 事件载荷、栈帧父子/帧号水位、挂起深度与槽位帧引用、
  选择号水位等结构关系未校验。
- **N05**：暂停点恢复此前只测散财链；杀/濒死/决斗/AOE/判定/弃牌/移伤
  等机器缺少「保存→恢复→继续同结果」矩阵。

## 决策

### 1. 弃置责任标志化（N01）

`NullifyWindowMachine` 增加 `owns_disposal`：单次结算锦囊（决斗/铁索/
延时锦囊）窗口抵消时弃置锦囊（true）；AOE 逐目标窗口为 false——无论
抵消与否都由外层 `AoeResolveMachine` 在全部目标结算后统一弃置一次。
`owns_disposal` 入机器快照与摘要编码。测试以**牌区守恒断言**
（每张目录牌在 deck/discard/table/手牌/装备/判定区恰出现一次）守护。

### 2. 判定中死亡清空剩余队列（N02）

`JudgePhaseMachine` 检测到拥有者死亡时，把队列中待判锦囊逐张弃置并写
`CardDiscarded` 日志后结束——死亡清空所有区域的规则对「已取出、在机器
队列中」的牌同样成立。

### 3. 闪电转移复用同名限制（N03）

闪电未命中转移时，自下家起扫描首个「判定区无闪电」的存活玩家；无合法
接收者（全部存活玩家判定区都有闪电）则弃置该锦囊。语义登记于覆盖清单。

### 4. 快照结构校验与身份/胜负一致性（N04，部分完成）

- `validate_core` 新增：身份局身份列表长度与座位数一致、组成合法
  （恰一主公、恰一内奸、至少一反贼）；原型局 `Winner::Player` 座位在界内；
  胜负与模式一致性（身份局不得有玩家胜者、原型局不得有阵营胜者）。
- 新增 `validate_event_data`（检查传入的事件载荷 ID）、`validate_stack`
  （帧号唯一且小于分配水位、父子关系检查、栈底无父、
  队列触发项 ID、载荷 ID）、`validate_resolution`（挂起深度 ≤ 当前栈深、
  槽位帧必须在栈上、选择号小于分配水位、应答选项 ID）；`Engine::restore`
  接入上述入口。**OptionalGate.event 尚未调用事件载荷检查；父节点检查仍误接受自身 id；
  选择与挂起机器的关联未校验**，三个反例均已独立复现，详见重写进度 N04-a/b/c。

### 5. 首轮暂停点恢复矩阵（N05，部分完成）

通用往返基准：同一布阵双线运行——基准线直跑收集应答序列与终态；快照线
从首个挂起点的快照恢复，每个选择点「保存→恢复→应答」，比对每点与终态
的规范摘要。基准终态与快照终态摘要也作比较，但未逐步对照基准选择和后续日志。

| 测试（`pause_roundtrip_*`） | 当前路径 | 尚不能据此证明 |
|---|---|---|
| `sha_respond` | 持闪时选择 Pass | 打出闪、技能响应替代等分支 |
| `dying_save` | 持桃时选择 Pass | 救回及判定→伤害→濒死嵌套续行 |
| `duel_respond` | 对方持杀，选择 Pass | 双方连续出杀、主动无懈/反无懈 |
| `aoe_mid_queue` | 两个目标持杀，逐个 Pass；没有无懈持有者 | 目标无懈链与洗牌期间牌区守恒 |
| `judge_window` | 乐的判定窗口持无懈者 Pass | 闪电伤害/濒死暂停、改写或抵消后的去向 |
| `discard_to_limit` | 选前 min 张牌弃置 | 其他选择组合及后续触发链 |
| `yishang_chain` | 确认移伤并选择目标 2 | 动态禁用、更多转移链组合 |

七类矩阵已有实质覆盖；helper 最多循环 12 次，尚未明确断言无剩余开放选择。
同步机器可能保存在暂停的祖先机器树里，但上述测试不足以证明每种嵌套树均已恢复验证，
尤其 JudgeTrick 发出闪电伤害后可随濒死救援暂停。补齐分支、完成态和事件增量对照后再关闭 N05。

## 验证（2026-09-16，独立复跑）

- `cargo test --offline -p engine-native`：86 passed / 0 failed；后续总数统一见重写进度。
- 机制测试 45→48：新增 N01 弃牌守恒（含 `assert_zone_conservation`）、
  N02 判定中死亡清队列、N03 转移绕行三项。
- 边界/快照测试 17→33：新增结构负向 9 项（父子链断裂、挂起深度越界、
  槽位帧悬空、重复帧号、载荷越界、队列触发越界、选择号越界、身份篡改
  用例含清空/非法组成两种变更、胜负模式错配）与 N05 矩阵 7 项。
- 14 个 golden 全部保持一致（N01–N03 修复路径不在 golden 覆盖内），
  未重录；编译仍有 unreachable pattern、未使用变量等警告。
- 独立探针复跑上轮四个反例，均已修复；另复现 N04-a/b/c 三种非法快照仍被接受，不计为测试通过项。

## 限制与后续

- 先完成 N04 剩余检查与 N05 扩展验收，再推进 N06–N12 的规则对照、时间片、正式技能、性能与平台。
- N01–N03 原反例已关闭；多目标抵消、洗牌、濒死救回、转移一圈/无接收者等扩展回归归 N05，
  无懈后闪电去向等规则决策归 N06，不能在“原反例已修复”时一并视为已验收。
- 守恒辅助断言目前只遍历核心牌区，适用于所测完成态；判定队列等机器暂持的牌未计入。
  若验证暂停态，应把执行机器持牌计入逻辑所有权，不能简单要求所有目录牌都在核心牌区。
