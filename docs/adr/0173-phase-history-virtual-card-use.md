# ADR 0173：阶段历史与阶段末无实体普通用牌

## 状态

已接受（2026-07-23）。

## 背景

旧版「据峻」「壁险」在任一具体阶段结束时，组合判断拥有者是否在该阶段成为过用牌目标、当前
体力是否实际变化，再强制使用【万箭齐发】或【决斗】。直接执行 archive JavaScript 会绕过权威
事件、Choice、快照和包 ABI；保存完整事件对象又会让状态随用牌数量无界增长，并把实现细节泄漏
进确定性状态。

## 决策

Rule VM ABI 98 增加 `phase_any_end` 和
`choose_use_virtual_card(player, wanjian|juedou, self_skill)`：

1. 只有包使用对应阶段历史过滤器时，引擎才启用两张定长玩家位图，分别记录本阶段成为过用牌目标
   和当前体力实际变化的角色；
2. 初始目标和 `CardTargetAdded` 都记入目标位图；伤害、回复、失去体力、死亡和体力上限裁剪只在
   当前体力值确实变化时记入体力位图；
3. 每个 `PhaseEnded` 额外生成一次 `PhaseAnyEnd` 上下文，携带阶段历史快照；历史在触发建立后
   立即清理；
4. 编译器只允许该虚拟牌效果出现在 `phase_any_end` 触发器，并把牌种收窄为【万箭齐发】和【决斗】；
5. 宿主先以现有目标策略做非变更合法性检查，再生成无花色虚拟牌。【万箭齐发】使用完整合法目标
   集；【决斗】打开不可取消的单目标 Choice，恢复时重新校验技能、实体牌、候选和目标；
6. 两种牌都进入普通用牌、目标、无懈、响应、伤害和弃置管线。内部
   `FinishPhaseEndVirtualCard` 尾请求跨越所有嵌套 Choice，最后再清理并解除历史抑制，防止阶段末
   用牌污染下一阶段。

archive JavaScript 只作为语义合同，不进入 DSL 包或运行时。

## 后果

- 阶段历史空间只随最大玩家数固定增长，不随上千技能或阶段内事件数量增长。
- 单纯降低体力上限但未裁剪当前体力时，「壁险」仍按“体力未变化”处理。
- 阶段结束技能产生的目标与伤害不会泄漏到下一阶段。
- ABI 97 主机拒绝 ABI 98 包；ABI 98 主机继续加载 ABI 3–97 的加法式内容包。
