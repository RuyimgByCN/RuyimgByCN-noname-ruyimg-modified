# ADR 0159：逐伤害点的体力上限封顶补牌

## 决策

ABI 84 增加触发过滤器 `owner_is_target_per_damage_point`。当拥有者是实际受伤角色时，每一点伤害
各生成一次独立触发；伤害可以来自自己、其他角色或没有来源。

DSL 同时增加 `choose_target_draw_to_max_hp_cap(player, cap)`：发动者必须选择任意一名存活角色，
目标将手牌补至其体力上限与 `cap` 的较小值。已经达到或超过该数量的角色仍是合法候选，结算为
无操作。选择恢复时重新校验存活状态，并按最新体力上限和手牌数计算补牌量。

## 原因

旧版 `jieming` 通过 `getIndex(event) = event.num` 对每一点伤害分别发动，并允许选择任意角色将
手牌补至最多五张。将重复次数和动态补牌分别建模为通用触发器与通用选择效果，可复用现有可选
触发队列和权威 continuation，无需为技能 ID 增加宿主分支。

## 结果

- 旧 JavaScript 仍只作为语义规格，不在运行时加载。
- 多点伤害的每次发动可独立接受、拒绝和选择目标。
- 等待选择期间目标死亡、体力上限或手牌数变化都会按最新权威状态处理。
