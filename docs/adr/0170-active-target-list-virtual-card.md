# ADR 0170：主动技目标列表上的无实体虚拟牌

## 状态

已接受（2026-07-23）。

## 背景

旧版「独探」在出牌阶段限一次，不选择或消耗实体牌，而是视为使用一张可指定任意名角色的
【决斗】。现有主动技已经能验证并保存完整目标列表，VM 也能读取该列表，但
`use_virtual_card_on(player, kind, target)` 只能表达一个显式目标；普通【决斗】流程还会把目标数
限制为一。为单个技能复制无懈、决斗响应或伤害结算会造成第二套规则路径。

## 决策

Rule VM ABI 95 增加
`use_virtual_card_on_selected_targets(player, juedou)`：

1. 编译器只允许它出现在声明至少一个 `other` 目标的主动技中，当前卡牌种类收窄为【决斗】；
2. VM 把本次 `ActivateSkill` 已验证的有序、互异目标列表复制进类型化 `EffectRequest`；
3. 宿主生成一张无花色、无实体定义的虚拟【决斗】；
4. 主动技目标契约替代普通【决斗】的一目标数量上限，其余卡牌使用策略、无懈与逐目标决斗队列
   全部复用现有实现。

archive 中的 JavaScript 只提供语义合同，不进入 DSL 包或运行时。

## 后果

- 「独探」只包含主动窗口、次数、目标合同和一个通用效果，没有技能名专用的 Rust 分支。
- 陈旧、重复、自身或已死亡目标仍在命令与结算边界被确定性拒绝。
- 只产生一张虚拟牌和一次 `CardUsed`，多个目标按提交顺序进入既有决斗队列。
- ABI 94 主机拒绝 ABI 95 包；ABI 95 主机继续加载旧的加法式内容包。
