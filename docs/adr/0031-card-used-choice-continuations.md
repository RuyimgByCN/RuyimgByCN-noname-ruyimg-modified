# ADR 0031：用牌触发选择与原牌续跑

## 决策

`PlayCard` 在派发 `CardUsed` 前保存可序列化的后续结算：杀恢复响应队列，普通锦囊恢复无懈可击
窗口。铁索连环和延时锦囊也统一经过 `EffectRequest::UseCard`，确保目标、用牌历史与 `CardUsed`
触发只有一套权威语义。Rule VM 新增通用的“从自己的手牌或装备区强制选择并弃置一张”效果，
首个使用者是义拒；旧 JavaScript 只作为迁移证据，不进入对局运行时。

## 原因

此前 `PlayCard` 先派发 `CardUsed`，返回后才创建杀的响应或锦囊的无懈窗口。若触发技能在中间
打开选择，命令会停在该选择上，原牌剩余结算没有可恢复的状态。把续跑点放在共享用牌路径，
可以同时修复现有和后续所有会在 `CardUsed` 阶段打开选择的技能，无需为每个技能保存私有状态。

## 兼容性

新增效果、筛选器和续跑标签均追加在旧枚举末尾，旧 npack 与快照的已有序号不变。完整对局的
事件和用牌历史会因铁索连环、延时锦囊进入统一 `UseCard` 路径而有意变化；8 人种子 99 的
Native golden 对局哈希从
`737fbf816bea652528c6e81f9805b31b71319dcb904b72d6155ee699a38de762` 更新为
`ce5e5b522e7ccc99be2b151c3f9e1ebf10e66ffc5d6f7bbc8623503e3e35f6a4`，其余已固定对局向量不变。
`EngineSemanticsId` 从修订 14 升至 15，Native、浏览器 WASM 与 skill-vm 必须重新通过跨目标
一致性门禁。
