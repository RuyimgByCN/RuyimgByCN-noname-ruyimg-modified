# ADR 0069：按存活人数上限补牌的触发过滤

## 决策

- DSL 增加 `owner_alive_hand_below_alive_count_capped_seven` 与
  `owner_is_source_hand_below_alive_count_capped_seven` 两个触发过滤器。
- 两者统一以 `min(7, 存活角色数)` 为阈值；前者用于全局开局事件，后者额外要求技能拥有者
  是事件来源。
- `挫锐` 的 VM 内容只负责计算并补足差额，是否需要询问由过滤器在创建 optional choice 前决定。

## 理由

旧 JS 在手牌已达到阈值时不会询问发动技能。仅在 VM 内容中判断虽然不会多摸牌，却会产生无意义的
可选提示，改变玩家可观察语义。该阈值判断也可供同类“补至场上人数且有封顶”的技能复用。

## 兼容性

新增枚举成员只在末尾追加；引擎语义修订号递增到 53。标准武将池和既有对局起始状态不变。
