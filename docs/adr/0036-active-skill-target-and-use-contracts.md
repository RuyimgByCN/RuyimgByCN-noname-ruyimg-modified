# ADR 0036：主动技目标与次数契约

- 状态：已接受
- Engine semantics：20

## 背景

旧 JS 主动技通过 `filterTarget`、`selectTarget` 和 `usable` 在客户端流程中约束目标与次数。仅把技能体编译为 typed effects 会留下命令绕过：调用方可提交零个、多个、重复、已死亡目标，或在同一回合重复发动。

SP2「凶算」要求出牌阶段限一次、选择一名角色并弃置一张手牌，正好需要把这些约束纳入可验证的扩展包契约。

## 决策

主动技声明新增两个可选子句：

```text
active play_phase uses_per_turn 1 targets 1 1 select_hand 1 1 {
  ...
}
```

- `targets min max`：引擎校验目标数量、目标互异且仍存活；是否允许选择自己由技能体语义决定，本契约不擅自排除。
- `uses_per_turn N`：引擎在执行技能体前校验 `SkillInstance.use_count`，并复用既有回合开始重置机制。
- 两项元数据进入 npack 逻辑哈希；缺省时不写入新增哈希域，因此旧包保持兼容。
- 卡牌输入继续复用 `select_hand min max`；凶算的弃牌、普通伤害、摸牌、体力流失全部复用既有 typed effects，不新增技能专用效果。

## 结果

主动技的结构约束由服务器/核心引擎权威执行，UI、自动运行器和网络调用方不能绕过。后续迁移同类旧 JS 时只需声明契约和组合通用效果。

多目标组合的策略选择仍属于 UI/AI；本 ADR 只定义并验证合法性，不把目标选择算法写入内容运行时。
