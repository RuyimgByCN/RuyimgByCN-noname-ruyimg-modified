# ADR 0169：当前【杀】绑定的目标牌分支

## 状态

已接受（2026-07-23）。

## 背景

旧版「鞬出」在【杀】指定目标后选择并弃置该目标的一张手牌或装备牌，再按所弃牌的实际类型分支：

- 装备牌：当前目标不能响应这张【杀】；
- 非装备牌：若当前实体【杀】仍在事件区域或弃牌堆，目标获得它。

现有 DSL 能选择目标牌，也能修改当前【杀】或取得事件牌，但不能在一次可暂停 Choice 后按所选
目标牌的有效类型安全分支。把旧事件对象或任意 JavaScript 带入运行时会破坏快照、重放和沙箱边界。

## 决策

Rule VM ABI 94 增加窄而可复用的效果
`choose_discard_target_card_resolve_current_sha(source, card, target)`，并仅允许用于
`card_targeted` 触发。宿主：

1. 验证 `source`、`card`、`target` 仍对应当前【杀】目标；
2. 复用标准目标手牌/装备牌 Choice；
3. 在 Choice 续体中保存稳定 ID，并在提交时再次验证目标牌和当前【杀】；
4. 弃置所选牌；有效类型为装备时令当前目标不可响应，否则让目标获得仍可取得的当前实体【杀】。

触发过滤器 `owner_source_sha_target_alive_has_discardable_hand_equip` 只负责建立可发动窗口；目标牌
的最终合法性仍由 Choice 提交路径决定。archive 中的 JavaScript 仅作为语义合同，不进入 npack。

## 后果

- 「鞬出」只声明触发条件和通用效果，技能身份不会写入引擎。
- 目标离场、牌区变化或当前【杀】续体失效时，恢复阶段确定性拒绝陈旧选择。
- 所有移动、响应修改、快照、重放和 canonical hash 继续复用既有引擎路径。
- ABI 93 主机拒绝 ABI 94 包；ABI 94 主机继续加载旧的加法式内容包。
