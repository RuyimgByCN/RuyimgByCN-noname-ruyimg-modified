2. **规则 v328→v329**，v329 仅由本 J2 批占用。依据是原生新增主动技执行、真实选牌/选人及对应效果结算；golden 先归因再决定重录。若在实施前已有其他授权批实际占用 v329，重新确认实际版本，不复用同号。
3. **全局原生 rule-vm 宿主 ABI 753→758**，前提是下表三类原语及拒绝矩阵全部实现并通过，不能只提高整数或放宽检查。754/755 为当前登记空号。保留 B6 对含歧义 tag 656 的 ABI 754–757 包/旧锁拒绝政策、ABI 745 英逝语义及 onlyOL 旧包原件。
4. **归档格式预计保持 v105**：提交期挂起沿用现有 Rvm 状态载体，必要字段按当前尾追加机制编码、摘要及验证同源维护。v328 及更早原生规则档依现有版本门禁明确拒绝，不在本批引入历史格式自动迁移；冻结包副本与旧锁原件继续保留。若实际证明必须升归档格式，先另行提出具体方案并确认，不能据此擅自改为 v106。
5. 复用现有 `GameAction::ActivateSkill`、`Answer`、ChoiceKind 和受限 prompt 键机制。允许按现有方式尾部登记本批所需静态 prompt 键（不移位旧 tag）；不新增 ChoiceKind 变体、参数化 prompt 载荷或新的 Worker/WS 命令形态。若这些约束无法表达实际语义，实施该扩展前再裁决。

## 已核对源码所显示的工作量边界

- `PackageActiveEntry` 已有 window、selection、targets、turn/play-phase 限次及状态条件字段；当前 `bridge_vm_skill_decls` 只遍历 `trigger_index`。桥接应校验真实 entry pc、逻辑技能身份与已有声明，未支持的声明须明确拒绝，不能静默忽略。
- onlyOL 0.1.5 要求 ABI 758，含 4 条主动技声明；胆守为 `ol_jie_danshou_active_play_phase_0`，外层 targets=0..0，实际交互由复合效果完成。其 phase_play 触发部分负责清零四项私有状态，必须与 active 部分一致，不能用不同模块名造成状态分裂。
- **ABI 不是 onlyOL 整包的唯一阻断**：整包还包含 phase_prepare（三条）、game_started（一条）、hand_compare_finished（一条）及其他滤镜/效果需求。N01 真实 DSL 子包可以验证本批机制，但不能据此把 onlyOL 整包或 37 来源标成完成；原整包缺口仍须按迁移计划继续补齐并真实重装验收。
- DSL `ol_pingkou.skill` 的旧注释仍写“只伤害不摸牌”，与现有已修旧线实现记录不一致；实施时以当前源码、上游和有效回归核对后同步注释，不能照注释复制缺失效果。

## 本批退出门槛

- 先有可暴露原生无主动入口、状态身份分裂/选择缺失的红灯，再修共享桥接、能力校验及提交泵；不以 debug_grant、修改 ABI 数字或删除拒绝测试证明正式入口完成。
- 正式作者产物经本地及服务端导入/安装、启用、选将/开局、实际发动、选择、存读档、升级/回退/停用/卸载验证；完整包未通过时明确保留未验收状态。
- 胆守四分支、限次/阶段重置、非法/取消、同键重试、每个挂起点字节恢复及跨进程续行；平寇逐目标伤害与实际摸牌；冯河双分支及防伤时序，分别有上游/旧线对照。
- 同状态/事件/RNG/续行轨迹、native/WASM 对照、旧包/旧锁拒绝矩阵；关联 crate 全量、engine-native 全量和 Gate 1b、workspace/conformance、前端与当前源码重建 WASM 后正式 Worker/产品路径、行数与 preflight 通过。
