- **Finding: P1 — Full-page reloads can leak native validator resources and exhaust the eight-resource limit.**

  [ExtensionsView.vue:35](/var/folders/b5/2mh_j5tj7m71xhcjsk2z1t4c0000gn/T/noname-pa09-76hf4fur/worktree/apps/web-client/src/views/ExtensionsView.vue:35) disposes its validator only through Vue’s `onUnmounted`. A document reload does not run that application unmount path. The native transport releases its resource only when `terminate()` invokes `native_engine_close` in [desktopEngineTransport.ts:74](/var/folders/b5/2mh_j5tj7m71xhcjsk2z1t4c0000gn/T/noname-pa09-76hf4fur/worktree/apps/web-client/src/engine/desktopEngineTransport.ts:74).

  These resources belong to the native WebView object, which survives document reloads. Tauri’s installed page-load handler retains that object and does not clear its resource table: [Tauri manager/webview.rs:288](/Users/ruyimg/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/tauri-2.11.5/src/manager/webview.rs:288). The application registers no native page-load cleanup in [main.rs:133](/var/folders/b5/2mh_j5tj7m71xhcjsk2z1t4c0000gn/T/noname-pa09-76hf4fur/worktree/apps/desktop-client/src/main.rs:133).

  **Source-derived reproduction:** opt into native, use the extension importer so it creates its validator, reload that document, and repeat. Each old validator remains held by its resource-table entry, retaining its session and waiting execution thread. Once eight entries remain, subsequent native connections receive `native engine resource limit reached` from [native_engine_resource.rs:13](/var/folders/b5/2mh_j5tj7m71xhcjsk2z1t4c0000gn/T/noname-pa09-76hf4fur/worktree/apps/desktop-client/src/native_engine_resource.rs:13). JavaScript garbage collection cannot release those native entries.

  **Smallest reliable fix:** close this document’s native-engine entries at native document teardown/navigation, scoped to `NativeEngineHost`; preserve unrelated resources and the distinction between queued work and an already executing command. Adding the extension page’s missing `pagehide` disposal would improve consistency with `BattleView`, but asynchronous JavaScript cleanup alone does not cover renderer loss. Add a reload regression that repeatedly creates a validator and reloads the same WebView, then verifies another native client can still connect. The existing WebView harness tests explicit disposal and resource close, not document replacement.

- **Correct — Ownership, ingress bounds, and replacement atomicity are implemented.**

  [native_engine_host.rs:26](/var/folders/b5/2mh_j5tj7m71xhcjsk2z1t4c0000gn/T/noname-pa09-76hf4fur/worktree/apps/desktop-client/src/native_engine_host.rs:26) creates one execution thread and an eight-slot channel per host. The session is constructed inside that thread. The resource contains the channel sender and synchronization state, with no new unsafe `Send`/`Sync` implementation.

  Explicit resource close removes the sender and marks queued work for rejection; an executing command may finish. Channel loss reports an unknown result. Resource-table allocation counts actual host entries under the table lock, and the capacity test allocates eight real entries, rejects the ninth, closes entries, and verifies replacement allocation.

  Typed deserialization rejects invalid numeric representations and narrowing overflows. Explicit checks cover safe-integer request IDs, seeds and choice IDs, valid start observers, and the specified archive/package text caps. Start constructs and projects a candidate before replacing the live session. Restore validates the candidate envelope before restoring the live session, preserving planner settings. The invalid restored-observer test verifies that failure leaves the previous archive intact.

  The eight-request bound applies to **Rust ingress**. The frontend Promise chain serializes invocations and has no separate backlog cap, so the implementation should not be described as bounding the entire client request pipeline.
