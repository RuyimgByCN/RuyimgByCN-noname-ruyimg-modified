建议最小合同（批准后才实现）：
| 载荷／宿主 | 承诺行为 |
|---|---|
| schema3旧包 | 缺省timing=normal、priority=0、order_selectable=true；不改原字节/manifest/hash/version。新宿主继续读默认包，显式写出完全相同默认值也只能产生相同排序语义。 |
| schema3带任一非默认排序 | 新宿主的parse后validate、public bridge、正式导入、冻结恢复和legacy入口一律拒绝；即使重算了新hash也拒绝。不能自动忽略或运行时默升schema，作者须重新发布schema4新版本。 |
| schema4新包 | 至少一条trigger有非默认排序；允许其余条目省略默认值。字段为timing∈{normal,first,last}、priority为effective i32、order_selectable为bool，默认同schema3；未知timing、非整数／越界priority、非法bool拒绝。不由optional、locale或tooltip推导。 |
| schema4但全默认／未知schema | 本方案不产出全默认schema4，验证也拒该非规范组合；schema0、未来5及其他未支持值不得以“>=3都兼容”放行。只接收明确支持的3/4数据契约。 |
| 新原生host与旧native host | 新host公布支持schema4并显式支持schema3默认，旧native/tooling host3拒4；format1/API1/ABI758其他轴保持。禁止只把常量3→4后继续精确相等，导致原schema3全部失效。 |
| 新legacy engine-core | 保持schema3默认包原行为；对于本次非默认排序包明确拒绝，不借本补充把旧调度器改成C规则。共享兼容层可认识4，不等于legacy执行层支持4。 |
| 旧档／冻结包 | 新C规则仍按规则版本拒330及更早NGSA；schema3包能被新局装载不意味着旧规则档可恢复。旧字节、包版本、安装副本/锁、冻结JSON和匹配旧执行路径保留；不改头、checksum、logic_hash或旧锁伪造迁移。 |
新schema4合同只保证合规新产物被旧bridge拒绝。若恶意把其manifest改成schema3，旧binary反序列化又丢掉新字段，旧低层bridge可能接受；新宿主必须拒这种降级，旧正式读者应因hash不符拒绝。不能通过修改新host追溯修好旧binary；若验收要求旧低层bridge对这种伪装也必拒，本方案无法满足，需明确旧执行程序停用/升级等另行处置，不能写成已关闭。
