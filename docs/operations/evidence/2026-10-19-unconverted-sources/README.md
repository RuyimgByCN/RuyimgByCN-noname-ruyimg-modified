## 5 ⚠ 第四轮：**「179 个技能」这个数字站不住**（自我更正）

第 3 节我写「真正欠的迁移工作量 = **179 个技能**」——**依据是台账 G0 的统计**。本轮**实际打开源码抽样**后，
发现 **G0 的「技能数」不能直接当「待迁移技能数」**：

### 5.1 L14（手杀ui）的「技能」是 **UI 钩子**

```
lib.skill._dieNoTuoguan = { trigger:{player:"dieAfter"}, content:function(){ ui.autonode.hide(); } }
lib.skill._jd_wjsw      = { trigger:{global:['phaseEnd','useCardAfter']}, content:function(){ game.as_removeImage(); } }
lib.skill._chupaiB      = { trigger:{global:[...]}, content:function(){ … getElementsByClassName("playertip") … } }
```

⇒ 三个**最小**的技能全是 **DOM/图片/提示条**操作，**没有一条规则效果**。
按 ADR 0782（UI 面不迁），它们**不是待迁移的规则技能**。

### 5.2 L08（十周年UI）的最小条目是 **标记桩**

`nzry_shicai_2`（34 B）、`mozhi1`/`mozhi2`（50 B）… ⇒ **标记/图标桩**，不是规则。

### 5.3 **数量本身也对不上**

| 来源 | G0 台账 | **本轮实测 `lib.skill.X=` 定义数** |
|---|---:|---:|
| L14 手杀ui | 48 | **92**（`extension.js` + `fonts/extension.js` **两份副本**）|
| L25 祖安武将 | 122 | **244**（`extension.js` + `extension_mess.js`）|
| L08 十周年UI | 9 | **332** |

⇒ **差异来自**：① **同源文件两份**（翻倍）② **统计口径不同**（G0 可能只数某些文件）③ **单位不同**（有的数 `lib.skill`，有的数武将引用）。

### 5.4 更正后的结论（**如实**）

1. **「179 个技能」不成立** ❌ —— 它是**把三个不同口径的数相加**得来的，**没有逐条核对**；
2. **待迁移量目前无法给出** ❌ —— 必须先做**逐源分类**（`trigger`/`content` 语义 ⇒ **规则技能 / UI 钩子 / 标记桩 / 重复副本**）；
3. **L14 的抽样表明其「技能」多为 UI 钩子** ⇒ 若全源都是如此，**实际待迁移量会显著小于 G0 数字**；
4. **本轮未做任何迁移**，只**推翻了上一轮的数字**。
