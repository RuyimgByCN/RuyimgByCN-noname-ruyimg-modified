## 1. 奖惩与终局判定顺序

**上游事实**：同一次死亡的 `die` 内容里，
1. `player.dieAfter(source)`（`content.ts:12537`）——身份模式实现在 `mode/identity.js:3159-3190`，
   末尾调用 **`game.checkResult()`**；后者对普通身份局调用 `game.over(true/false)` 结算胜负
   （`mode/identity.js:820-980`，`game/index.js:6547` `over()` 置 `_status.over`）。
2. `player.dieAfter2(source)`（`content.ts:12615`）——**奖惩**：杀死反贼来源摸 3、平民摸 2、
   明忠按来源、主公杀死忠臣则主公弃全部手牌（`identity.js:3103-3156`）。

⇒ 上游顺序为 **胜负判定（checkResult/over）在前、奖惩在后**。

**原生**：奖惩先于终局判定（ADR 0705 决策，`last_rebel_reward_precedes_victory` 断言"末反贼奖励不被终局短路"）。

**判定与处置**：两线顺序**不同**。
- 原生选择（奖惩先）保证奖励计入终局前状态，与「死亡结算完整性」更一致；
- 上游 `game.over` 之后事件链**是否继续执行 dieAfter2**（`_status.over` 相关短路点）本批**未逐项确认**
  ——若仍发放，则该差异表现为**顺序与终局快照口径**；若被短路，则原生更符合"击杀反贼有奖励"的规则意图。
- 处置：**保留原生顺序**并登记；把"上游 over 后奖惩是否仍发放"列为**待核项**（需要时按新批次用上游差分
  证据确认后再决定是否改判）。

## 2. 死亡清技能（决策）

**事实**：原生在死亡结算时**删除技能实例**（实例表不再含死者条目）；旧线保留实例、以 `alive` 过滤
消费（观察面等价，**哈希面不同**）。上游为对象式技能表 + `getSkills` 过滤（无独立实例表，无此问题）。

**决策（本批作出）**：**保留原生"死亡即删实例"**，理由：
1. 采用玩法版本是**上游**，旧线只作迁移对照——跨线**原始哈希等价不是本项目目标**（见
   [采用玩法版本与距离语义基准](../2026-10-16-rule-source-distance-basis/README.md)）。
2. 因此"迁移哈希门禁"不应比较**跨线原始哈希**；同负载/跨线对照必须以**投影后语义**（可见状态、
   事件轨迹、终局结果）为准；原生线自身的哈希/存档一致性由 `canonical_hash` 与恢复矩阵守护。
3. 删实例使状态更小、恢复更严（无"死者僵尸实例"），且不改变任何观察面语义。

**登记**：本行由「迁移哈希门禁前需决策」改为「**已决策：保留原生；跨线不追求原始哈希等价**」，
并把"跨线对照口径=投影后语义"写入规则基准边界。
