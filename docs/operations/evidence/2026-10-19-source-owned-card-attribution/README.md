# 来源「自有卡」归属普查（全 10 个已转换包，2026-10-19）

- 工作包：**NC08 / 扩展台账**；规则版本 v322（工作树）/ 存档格式 v105
- 目的：区分「**包内卡名**」与「**来源自有卡**」——后者才是该来源的**行为面待办**

## 方法

对每个包的卡名，检查是否出现在**该来源上游的 `card.js`**（含 `type:` 的顶层键）；
**两侧都做前缀与尾部数字归一**（`swd_`/`gw_`/`gj_`/`ycn_`/`wd_`/`hl_`/`xz_`/`ow_`/`hearth_`/`mtg_`/`zf_`/
`hslingjian_` + 去尾部数字）。

> **归一化必须两侧都做**：首轮只归一**包内**一侧 ⇒ `gwent` 与 `swd` 被**整体误判为非自有**
> （`gw_*` 键与包内无前缀名不匹配）⇒ 修正后两者均为 **100% 自有**。
> 这是本会话**第四次**因「单侧归一」导致整批误判。

## 结论

1. **178/185 为来源自有卡** ⇒ 各来源的「自有卡」范围与包内卡名**基本一致**；
2. **7 项非自有**：`wudian` 5 项为**标准牌**（已核对，台账第 140 行）、`wuxing` 1 项格式特殊、
   `shahai-yunchou` 1 项**待逐名核对**；
3. **边界**：本普查只判「**卡名是否由该来源的 `card.js` 定义**」，**不判实现或语义等价**。
