## 7 差异①的**精确定位**：转化在「闪」响应已实现，在「杀」响应缺失（2026-10-19 同轮）

进一步核对**响应选项构造处**，发现原生**并非完全**不支持响应转化——**方向不对称**：

| 响应方向 | 构造处 | 是否含转化 |
|---|---|---|
| **闪**（`respond_shan`） | `kernel/sha/step.rs:693–1243` | **含**：`kind == Shan \|\| (longdan && kind == Sha)`（龙胆）+ `qingguo && black`（倾国）+ 诱敌深入/神弓 |
| **杀**（决斗 `duel_sha`） | `kernel/duel.rs:70` | **不含**：`filter(card_kind == Sha)` 只取**实体【杀】** |
| **闪**（无双双闪臂） | `kernel/sha/step.rs:369–392` | **含**：同上三臂 |

→ 因此差异①应精确表述为：**「杀」方向的转化（武圣红牌、龙胆【闪】）在响应路径缺失**，
而**「闪」方向的转化（龙胆【杀】、倾国黑牌）已实现**。**修法**据此收敛为「按 `respond_shan`
的既有模式，为**杀响应**补齐转化候选」（见[待实施修复清单](../2026-10-18-blocked-fixes/README.md) 第 7 项）。

**方法学（写入证据）**：判定「机制缺失」前应**枚举同类构造处**（此处为三类响应选项），
否则会把**局部缺失**误报为**系统性缺失**。
