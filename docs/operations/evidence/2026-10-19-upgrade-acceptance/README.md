## 结果

| # | 面 | 判据 | 实测 |
|---|---|---|---|
| 1 | **版本递增** | `version 1 → 2` ⇒ 目录内容**不变** | **214 → 214** ✅ |
| 2 | **卡牌增量** | 旧 N → 新 N+1 ⇒ **恰好 +1**，旧卡全在 | **214 → 215** ✅（旧卡全部存在） |
| 3 | **新旧并存** | 同进程先后构造旧/新包 ⇒ **互不影响** | old 214 / new 214 / old_again 214 ✅ |
| 4 | **降级** | 移除一张卡 ⇒ 桥接**仍成功** | 移除 `xuanyuanjian` 后 **桥接成功** ✅ |

**结论**：包数据是**不可变输入**（`bridge_pack` 每次从 JSON 构造、**无全局可变状态**）⇒
升级语义可机械验证为「**版本号无关内容** + **增量可加** + **无共享状态** + **缺卡不破坏桥接**」四件事。
