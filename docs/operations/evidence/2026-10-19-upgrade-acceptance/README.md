# 「升级」验收（八项验收第 2 项，2026-10-19）

- 工作包：**NC08 / 扩展台账**；规则版本 v322（工作树）/ 存档格式 v105
- 用例：`crates/engine-native/tests/nc08_upgrade_acceptance.rs`（**4 用例全通过**）
- 夹具：**swd 包**（90 张、双产物）作为「旧/新版本」样本

## 结果

| # | 面 | 判据 | 实测 |
|---|---|---|---|
| 1 | **版本递增** | `version 1 → 2` ⇒ 目录内容**不变** | **214 → 214** ✅ |
| 2 | **卡牌增量** | 旧 N → 新 N+1 ⇒ **恰好 +1**，旧卡全在 | **214 → 215** ✅（旧卡全部存在） |
| 3 | **新旧并存** | 同进程先后构造旧/新包 ⇒ **互不影响** | old 214 / new 214 / old_again 214 ✅ |
| 4 | **降级** | 移除一张卡 ⇒ 桥接**仍成功** | 移除 `xuanyuanjian` 后 **桥接成功** ✅ |

**结论**：包数据是**不可变输入**（`bridge_pack` 每次从 JSON 构造、**无全局可变状态**）⇒
升级语义可机械验证为「**版本号无关内容** + **增量可加** + **无共享状态** + **缺卡不破坏桥接**」四件事。

## 边界（**如实**）

1. **存档跨版本未覆盖**：用**旧包存档**、再用**新包读档**的一致性需要 `StateSnapshot` 构造
   （`encode_archive`/`decode_archive` 已存在，但快照构造需引擎侧钩子）⇒ **登记待办**；
2. **技能/寄存器升级**（如 `host_skills` 映射改名）未覆盖——本例只动 `cards`/`version`；
3. **降级**只验证「桥接不报错」，**未验证**语义（旧存档引用已删卡时的行为）。
