- [ai/remap.rs:124](/Users/ruyimg/Documents/Claude/sanguosha/noname-next/crates/engine-native/src/ai/remap.rs:124): remapping does not inspect `commit_state` or `following`.

J2 opens seven new prompts with VM execution already halted. Such a machine can have `committing = true`, nonempty `commit_state` and queued effects, while both `paused` and `commit_pick` are `None`. At an own-seat J2 choice, neither existing NC10 gate catches this state.

The consequence follows from the current execution path: queries execute while the VM builds its effect queue; later hand sampling changes physical cards but cannot undo a private query result already encoded in an effect’s scalar amount. `plan_action` then submits candidate answers and scores those retained effects.

**Concrete supported-DSL counterexample for validation:**

```text
active play_phase targets 0 0 {
  let reds = hand_color_count(2, red);
  effect resolve_ol_jie_danshou(self);
  effect deal_damage(self, self, reds + 1);
}
```

Formally compile and assign this skill. Give seat 0 four HP and hand `[spare Sha, Tao, Shan]`. Use Danshou option 1 on self and discard the spare Sha. The resulting `rvm_danshou_discard` window offers `[Tao, Shan]`, with exactly one card required.

Compare two states differing only in seat 1’s four hidden cards: all red versus all black. Their cached queued self-damage is five versus one. Their visible choice remains the same. Current code:

1. Misses the new prompt in `vm_choice_leaf`.
2. Allows sampling because neither old VM pause field is present.
3. Retains the privately derived damage amount.
4. Simulates discarding Tao or Shan and scores the resulting damage/rescue paths.

This exposes precisely the cached-private-effect dependency that the existing NC10 regression prevents for `rvm_discard_pick`; see [nc10_opaque_vm_privacy.rs:205](/Users/ruyimg/Documents/Claude/sanguosha/noname-next/crates/engine-native/tests/nc10_opaque_vm_privacy.rs:205).
