# 包 → 上游来源映射：**41 包 / 35 声明 / 6 未声明 / 27 个来源目录**（2026-10-19）

- 工作包：**NC08 / 数字口径**
- 脚本：`scripts/list_package_sources.py`（**可执行、可复跑**）
- 输出：[packages.txt](packages.txt)（逐包）、[summary.txt](summary.txt)（按来源汇总）

## 1 为什么需要这个脚本

**包数据里没有统一的来源字段** ❌：

| 声明位置 | 例子 |
|---|---|
| `assets/config.json` 的 `upstream_path` | 多数包 |
| **`assets/cards.json` 的 `upstream_path`** | **`shaai-ow`/`shahai-swd` 等 `杀海拾遗` 子包** |
| **两处都没有** | **6 个包**（`cardpile`×2 / `coin-noname` / `d3` / `desktop-adapt` / `omnisearch`）|

⇒ **任何「按来源统计」的脚本必须同时读两处**，否则得到互相矛盾的数字
（本会话已因此产生多次错误结论：**「22 有资产包」❌、「13 = 上限」❌**）。

## 2 结果

```
包数 41；有 upstream_path 35；未声明 6
来源目录数（去重）：27
```

**最大的来源**：**`杀海拾遗` = 9 个包**（`shaai-ow`/`shaai-xianjian`/`shahai-{gujian,gwent,hearth,mtg,swd,yunchou,zhenfa}`）
—— **这解释了「组合」为什么有大量对数**：**单来源 9 包两两组合 = 36 对**。

## 3 与 37 个来源的关系（**重要口径**）

| 数字 | 含义 | 值 |
|---|---|---:|
| **37** | **上游来源实例数**（任务范围）| 37 |
| **27** | **包声明里出现的「来源目录名」数** | 27 |
| **6** | **未声明 `upstream_path` 的包** | 6 |

⇒ **27 ≠ 37**：**差额是「没有转换包的来源」**（**G1 未做**）+ **部分包的路径写法不同**（**一个上游来源可能被拆成多个目录名**）。
⇒ **因此不能用「27」代替「37」，也不能用「41」当来源数**。

## 4 边界

1. 脚本**只读包数据**，不读台账 —— **台账的「来源 ↔ 包」对应仍需人工核对**；
2. **6 个未声明包**需要补字段（**属包数据质量问题**，本代理可改 `assets/**` —— 但**改包会变更内容锁**，需评估）；
3. 本脚本**不含**「有资产」判定（那是另一个脚本/证据）。
