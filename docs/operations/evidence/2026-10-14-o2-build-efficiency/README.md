# O2 构建效率测量 + 合并试点（2026-10-14）

## 任务来源与口径

[进度主稿 O2](../../../architecture/native-progress.md)：先确认空闲磁盘，在**独立 `CARGO_TARGET_DIR`** 固定工具链/机器/起始状态，测 `engine-core` 干净/热态 `cargo test --no-run` 的耗时、链接目标数、磁盘；不清理并行代理共享的 target。完成条件：试点前后测试名/数量/过滤行为相同、全套通过；据数字决定是否扩大合并，不预设收益。

环境：git `556e6ad4`；rustc 1.95.0 / cargo 1.95.0；Apple Silicon（本机）；磁盘可用 80Gi；独立 target=/tmp/o2-engine-core（用后已删，54→58GB）；被测对象 engine-core：src 83 文件/212,525 行，tests **1,078 文件**（即旧报告「1,078 文件」的实际所指——每个集成测试文件编译为独立测试二进制）。

## 合并试点（机制验证）

8 个最小数据断言测试文件（18–40 行）平铺合并为 `tests/original_small_pack_asserts.rs`：

- **#[test] 函数名与数量逐一相同**（git HEAD 逐文件提取比对 8=8）；const 顶层名按来源加前缀防碰撞；文件中部 `//!` 转普通注释（E0753）。
- 合并目标 8/8 绿；**engine-core 全套 3,778/0/0（exit 0）**——「试点前后测试名/数量/过滤行为相同、全套通过」满足。

## 结论与决定

- **瓶颈定位**：增量/全套耗时的主导项是 **1,078 个独立测试二进制的链接成本**（∝二进制数量），不是 src 文件数（83 个）；热态（零变更）无问题。
- **试点结论**：平铺合并机制可行（名称/数量/过滤行为不变、全套绿），但 8/1,078 规模无可测收益——收益与二进制数缩减成正比。
- **决定**：**全量合并（1,078→约 50–100 个按批次族分组的文件）为 91s 增量重链的主要杠杆**，另立项目（tests/ 25.6 万行重组，机械合并+逐批名称比对）；O2 本项（测量+试点+决策）闭环。不预设收益百分比——按全量合并后的实测为准。
