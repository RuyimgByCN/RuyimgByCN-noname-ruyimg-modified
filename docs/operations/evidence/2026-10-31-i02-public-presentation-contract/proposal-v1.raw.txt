## Proposed typed metadata (all field names below need the specific decision)
- Add only `presentation?: PublicPresentationBatch` alongside existing `ServerMessage::CommandOutcome.public_event_codes` and frontend `EngineEnvelope.events`; do not replace those arrays. Rust field is `#[serde(default, skip_serializing_if="Option::is_none")] Option<PublicPresentationBatch>`; new DTOs belong to existing engine-api presentation surface and Rust projector, not a source/callback registry.
- `PublicPresentationBatch = { revision: u64, status: "complete"|"incomplete"|"overflow", unavailable: Vec<UnavailableScope>, occurrences: Vec<PublicOccurrence> }`. Integers on JS ingress must be safe nonnegative integers; existing counters above JS exact range remain a separately visible transport incompatibility, not rounded cue keys. `UnavailableScope = { domain:"card_use"|"card_response"|"skill_activation"|"damage"|"recovery"|"death"|"voice_identity", reason:"source_no_audio_discriminator"|"commit_boundary_unproved"|"public_binding_unavailable" }`; it carries no hidden identity/count.
- `PublicOccurrence = { ordinal:u32, event: PublicPresentationEvent }`. Ordinal is stable enumeration of **public committed occurrences** in existing log order for that accepted revision; it is not a new formal EventId/counter and does not expose raw private-log offsets. Native start/end cursor stays host-private. Project one identical public stream for owner/other/spectator/referee; no richer owner-only skill/audio payload, private counts, hand IDs or choice-source context in this member.
- `PublicPresentationEvent` is tagged `{ kind: ... }` with these concrete variants: `card_used {actor,targets,effective,voice_role}`; `card_responded {actor,effective,voice_role}`; `skill_activated {actor,skill,targets,voice_role}`; `damage_dealt {source,target,amount,nature}`; `damage_prevented {source,target,nature}`; `hp_recovered {actor,amount}`; `player_died {actor,killer,voice_role}`. `source/killer/voice_role` may be null; `targets` is null when no committed public target list exists, [] only when authoritatively empty. amounts are actual positive u32; prevented has no invented amount or private prevention reason.
- All typed `actor/source/target/killer/targets` use **existing API PlayerId**, 1..seat_count, null for no actor. Rust projection alone normalizes native0→API1; local existing snapshots remain native0 and WS snapshots API1, so the frontend normalizes its selected snapshot once before comparisons. Never accept actor0 as a player or mix player IDs with mutable seat order. No new player field in rule commands/state.
- `effective = { kind:string, key:string, nature:"normal"|"fire"|"thunder" }`: kind uses existing exhaustive `CardKind::key()` (`catalog/card_kind.rs:354`), while key is the committed **public use name**, not necessarily that kind key or a physical card face. Preserve catalog CardDef.name for unconverted named equipment/tricks; for use_as take the declared kind's semantic name, normalizing FireSha/LeiSha to `{key:"sha",nature:"fire"|"thunder"}` rather than voicing a physical red card. Existing kind keys `huosha`/`leisha` are not audio basenames `sha_fire`/`sha_thunder`. Unknown source identity remains explicit `source_no_audio_discriminator`, never guessed as Sha/Other/default speech.
- `skill = { def:u32, name:string }` identifies the actual native runtime skill under the frozen content set; it is not an original-content def_id or resource URL. `voice_role = { general_def:u32, name:string, slot:0|1, form:string|null }` is a **public occurrence-time** role certificate captured before transformation/removal, never the final snapshot guessed afterwards. Null means no publicly authorized speaker role. Form is only an actual public supported rule/substitute form; user-selected cosmetic skin is not a rule identity.
- Skill names/targets/voice_role may be emitted only when the actual activation itself and that identity are public. Use the existing public-general visibility rule `engine/views.rs:37–52` at **occurrence time** (others/spectators never see hidden slots); own/referee visibility does not grant public permission. Match general def/name and revealed/public state, exact provider/owner and actual cost/commit visibility. A truly secret activation produces no named occurrence or private-count hint; missing commitment support is separately declared at domain level, not encoded as a fake activation.

## Committed spans, transport and exact live admission
- `Engine.log` is separate from state (`engine.rs:155`); submit truncates rejected work (`commands.rs:180/:247`), Pending/Done commit and increment revision (:252/:298), Suspended commits tentative progress **without revision increment** (:265), and abort/fault can roll back (:57/:273). Therefore do not emit irreversible cues on every non-null result or every Yielded slice.
- Keep one private presentation watermark into the existing log per host handle/session (no event queue); retain the segment start across Suspended/resume, release only once the segment closes Accepted or Pending, using its final revision. Terminal Pending means committed up to a real choice, not that its skill is already activated. While suspended publish no presentation batch; on abort/fault/rejection discard pending span and reset watermark to the authoritative current end. Do not reuse code cursor advancement as proof of commitment.
- Never blindly reopen a rejected span: open-segment fault handling `commands.rs:277` truncates the current resume mark while restoring a checkpoint, so old suspended log rows can remain. The presentation watermark must discard the entire held span on that outcome; compare full pre/post log+state in fault/abort tests. Server paths must release only after durability.commit success (`room_native_actor.rs:545–557`, `room_native_actor/timeout.rs:17–20`); rollback includes presentation watermark alongside existing `event_cursor` (`room_native.rs:111–164`).
- At release enumerate the complete public span once and emit one batch, with cue identity `(frontend session generation, batch.revision, occurrence.ordinal)`. Existing log order and committed command revision supply identity; no RNG, formal EventId, new command or public raw-log offset. Do not use conn_seq alone (unsolicited broadcasts use0), idempotency_key alone (automatic commands use0), or state hash alone (same-revision suspended progress changes it).
- Server normal reply and member broadcast carry the same batch after durable commit; each client uses only public metadata. Existing retained receipt `room_native/receipts.rs:7` stores kind/result, not events; retry `room_native_actor.rs:461–483` returns saved result/current view/empty codes. Keep retries presentation-absent and do not persist new receipt payloads: missed historical sound is not replayed on reconnect. Automatic timeout/takeover (:28–38) uses the same committed projector despite key0.
- Shared method proposal: `Engine::public_presentation_from(start_log_index)` returns a pure typed public span under current committed revision; host must gate invocation by terminal outcome and captured watermark. `NativeSession::public_presentation_json(start:u32)` serializes the same Rust projection; expose it as an additive optional wasm-bindgen JS method in `engine-native-wasm/src/lib.rs`, not a Rule VM host ABI/query. Worker tests feature-detect this method; old bundles report unavailable capability, never infer finer events from codes.
- Wire all existing callers: `worker/nativeBackend.ts:809/:843` + `engine.native.worker.ts`, shared `NativeSession`, desktop `apps/desktop-client/src/native_envelope.rs:127` / native_engine_host, server room/timeout actor, `networkClient.ts:629/:773`, TS `types/engine.ts:104`, and BattleView. IPC keeps native_engine_request and WorkerRequest/WorkerResponse; `desktopEngineTransport.ts:30` already spreads unknown envelope fields. Preserve the existing coarse events chain independently.
- At frontend ingress validate the **entire present batch** before changing revision/choice/store/pending storage/cursor or acknowledging a response; network currently mutates those before fine-event parsing (:629–644). Invalid-present metadata rejects the whole envelope atomically with bounded visible error; absent metadata is legacy-compatible. Rust typed deserialize uses deny_unknown_fields within the new DTO and strict tags/ranges; no coercive Number/string conversions, duplicate ordinals, mixed revisions, invalid/hidden identity, malformed form/path tokens or negative/NaN actor IDs. Source27 optional metadata validation is precedent (`engine-api/src/choice.rs:36–40/:102`).
- Successful admission marks occurrences consumed **synchronously** before any catalog fetch/play promise/presentation delay; release in log order. Keep only current generation's latest committed revision and bounded ordinal/cue admission state; duplicate/same revision batches must match prior identity/content or fail atomically, not enqueue twice. Reject stale batches even if the surrounding existing view refresh is useful; do not rollback newer audio baseline for an old result. SAB/postMessage share EngineClient's existing one-settlement map (`client.ts:102/:187`) and the same admission guard.
- Join/start/status/chooseGeneral/restore/snapshot establish a **silent baseline**, never infer missed cues from HP/cards/alive. Reconnect suspends playback and keeps live dedup until rejoin establishes a new baseline; pending retry is silent; accept only fresh committed batches after it. Retire old socket/transport callbacks with a captured local generation. New match/room/restore/observer/content-source change clears old async work/dedup and establishes a new generation+baseline; room ID reuse alone cannot inherit it. None needs a new wire session nonce.
- Replay seek/import/baseline stays silent; explicit sequential replay playback may admit reconstructed committed occurrences into a distinct replay generation, with rewind/observer change resetting baseline. Current native worker rejects loadReplay/seekReplay (`engine.native.worker.ts:141`), but this is an implementation gap, not a permanent exclusion. Deterministic reexecution of an exact full command log can reconstruct presentation with matched rules/content; archive-only or compacted WAL cannot recover discarded historical logs and must report unavailable history.
- Bound new metadata to1024 public occurrences and64KiB encoded, with nonempty identifier tokens ≤256 UTF-8 bytes and target count within existing16. Also respect total WS256KiB (`engine-protocol/src/lib.rs:20`) and existing IPC/SAB envelope limits. If complete metadata would overflow, send bounded `status:"overflow"` with no occurrences and retain the authoritative result/view/coarse codes; never truncate to apparently complete cues or fail a committed command because sound is large. Overflow remains an explicit unfulfilled presentation case for acceptance; SAB already falls back to postMessage when too large (`worker/stepTimings.ts:63`).

## One minimal frontend audio owner and resource lifecycle
- One BattleView-owned native HTMLAudioElement with one active source and pending queue≤8; no generic settings/WebAudio/decoded cache framework. Synchronous cue admission is independent of async playback; retain only bounded current-path error state. Queue overload drops oldest pending cue with bounded diagnostic, consumes its identity and never replays it later. “Exactly once” means one live admission/attempt per committed occurrence, not guaranteed audible success.
- Resolve original voices using existing `engine/originalResources.ts:18` backing/alias integrity checks and :11 URL validation. - Public role lookup is unique catalog name+runtime certificate under pinned source/content lock; verify supplied def/name against the actual authorized public GeneralView and static identity without conflating original def_id. - Bind original-content fetch origin to the existing local/online source configuration (`appearanceStore.ts:41/:54/:359`), not Collection's unrelated viewer-host7700 shortcut.
