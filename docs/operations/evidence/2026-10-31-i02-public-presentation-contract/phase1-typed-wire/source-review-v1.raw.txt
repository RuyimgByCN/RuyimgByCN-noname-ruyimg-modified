  **Source-derived repro:** return an otherwise normal successful IPC envelope with `presentation:null` and `view.seats[0].generals=[]`. Observer validation throws first; desktop converts it to `ok:false`; EngineClient clears pending instead of retaining the uncertain entry. Nested chooseGeneral follows the same path. Existing adversarial tests keep observer metadata valid, so they miss this combination. **Smallest fix:** preserve the raw successful response when its presentation is malformed, allowing the shared validator to reject before normal cleanup. Retain existing Source27 handling for responses without malformed presentation. Add compound-invalid direct/nested IPC cases asserting unchanged pending and receipt timing.

- **Finding — P1: Network malformed-response retention has no capacity bound.** The new [networkClient.ts:535](/tmp/i02-phase1-ab167599/acceptance-checkpoint/source/apps/web-client/src/engine/networkClient.ts:535) rejects a matching caller promise while retaining its pending entry, as required for uncertain execution. The new eight-request guard exists only in local EngineClient.

  **Source-derived repro:** repeatedly submit a command, receive a matching same-room positive-sequence outcome with `presentation:null`, catch the rejection, and submit another command. Each iteration retains another map entry; later reconnect replays every retained intent. This newly introduced immediate-rejection path permits unbounded retained entries even with sequential callers. **Smallest fix:** bound network admission before allocating/inserting/sending a new intent while preserving uncertain receipts and same-key recovery. Reuse the existing limit; add no queue or ledger. Cover repeated malformed replies, excess requests remaining unsent, and disposal/recovery cleanup.

- **Finding — P2: Rust and TS repository validators accept different string domains.** [Rust validation:22](/tmp/i02-phase1-ab167599/acceptance-checkpoint/source/crates/engine-api/src/presentation/validation.rs:22) uses Unicode `is_whitespace`; [TS validation:14](/tmp/i02-phase1-ab167599/acceptance-checkpoint/source/apps/web-client/src/engine/presentationMetadata.ts:14) uses ECMAScript `\s`. U+FEFF is rejected by the latter but is neither whitespace nor control under Rust’s checks. An otherwise valid owner with repository `"repo\uFEFF"` therefore passes Rust validation and fails TS ingress. **Smallest fix:** define the same explicit policy on both sides and add that shared fixture.

The positive S→C reader test remains useful.
