## 1. Authority: producer declaration, not a frontend historical certificate
- `engine-native/src/engine/views.rs:37–52` establishes native public-general visibility; own/referee visibility is broader. At the genuine occurrence, Rust alone evaluates public visibility, actual invocation/provider and public form, then copies the authorized immutable definition/resource binding into that LogEvent. Hidden provider/general/skill/sex/choice context must not escape through DTO, capability status, URL or error. Hashes and asset identity establish resource integrity, **not** permission to expose a private role.
- Explicit trust boundary: the frontend trusts that public declaration through the **existing authoritative local Worker/IPC or room transport**, just as it trusts the game view; this is not a cryptographic certificate. TS validates structure, integer bounds, frozen owner/resource equality and safe resource paths. It neither reads private snapshots nor independently proves occurrence-time visibility from the final GeneralView.
- Remove v1's final-slot equality test: `kernel/phase/judge.rs:221` can rotate the general during the same resolution. A valid earlier cue retains its old qualified role/resource binding even when the final slot contains another form or no general. Frontend must accept that earlier authorized binding when it belongs to the pinned verified source; final snapshot name/def/revealed mismatch alone is not rejection evidence.
- Producer tests, not frontend reconstruction, must prove public permission: paired other/spectator/own-hidden/referee inputs, hidden skill activation vs no activation, same-phase role rotation/removal, reveal→cue→transform and cue-before-later-reveal. An earlier hidden cue must remain absent even if a later slot is public; an earlier public cue must keep its original binding even if the final role differs. Public outputs must match across viewer privileges.

Legacy None is explicitly unbound capability, not evidence that the source has no audio.
- `DefinitionPresentationBinding` is passive leaf data constructed only inside the trusted content loader/factory: `{ definition: QualifiedDefinitionKey, voice_assets: existing logical-voice-key→ordered BoundAudioAsset candidates }`. QualifiedDefinitionKey is `{owner:FrozenOwnerKey, kind:"general"|"skill"|"card", local_id}`. For SDK local_id is the existing package character/skill/card id; original local_id is the explicit `{pack,raw_symbol}` source key, **not** a Chinese label. Kernel receives this immutable data and must not depend on PackageStore, filesystem, JSON or an upward content-runtime dependency.
- `FrozenOwnerKey` has two explicit representations within this single binding: package owner copies exact LockedPackage fields; imported original owner copies `{repository,adopted_revision,catalog_sha256,asset_manifest_sha256}` from verified frozen original presentation inputs. This is a resource-source discriminator, not alternate rule roots. The adopted original repository/revision currently declared by `catalog.json:10–18` is libnoname/noname `1a548c95acdf8ac1ef44d74473403eda2ac86cf0`; that provenance text alone does not verify bytes.
- `BoundAudioAsset` is `{source:FrozenOwnerKey, reference, digest_algorithm:"sha256"|"blake3", digest, size}`. Package reference reuses ActiveAssetRef and exact frozen version/content hash; imported reference is the existing six-field alias row's canonical path/source_category/source_path plus SHA256/size and matching backing. Do not convert SHA256 to a claimed BLAKE3 or use asset_hash in place of a payload hash. Existing paths become URLs only in the resolver, never in rule commands or private role records.
- **Exact loader input gap for SDK:** add optional `definition_id` to the genuine bridged `generals[]`/`cards[]` entries; for host skill entries add the corresponding package skill id where not already carried by VM metadata. Verified construction resolves that id to the **same frozen package's** character_index/skill_index/card_index (or an explicitly locked dependency for a builtin reference), checks declared rule linkage, and attaches the binding. Do not attach by name_key/display name or a caller-provided provenance string. Conflicting/missing identity with requested audio rejects binding construction atomically.
- Resolve package audio through existing `skin_index.skins[].character_id`, `voice_assets`, aliases/voice_mappings and declared audio manifest entries (`content-schema/package.rs:54/:148/:971`, `content-runtime/catalog.rs:216`). For base general/skill/card voices not expressible by those existing entries, the precise proposed addition is **optional `voice_assets` on that genuine PackageCharacterEntry/PackageSkillEntry/PackageCardEntry**, reusing the same logical-key→package-local audio asset-id type/validation. Form overlays remain the existing skin index; no second declaration interpreter or source-specific code registry. This field/loader addition needs explicit schema/hash review; current absence blocks full binding.
- **Exact builtin input gap:** add the explicit original source key inline to each genuine built-in general/skill/card definition's presentation property, e.g. standard Liu Bei `{pack:"standard",raw_symbol:"liubei"}` and its genuine skills `{pack:"standard",raw_symbol:"rende"/"jijiang"}`. Do not assign that binding to Boss 刘备 by label. A Boss key is populated only from its separately verified actual source declaration; otherwise it stays explicitly unbound, still in scope. Source-faithfulness of the cue binding is tested independently of rule-equivalence claims.
- For imported originals, the controlled factory also requires frozen raw `catalog.json` + schema2 `asset-manifest.json` whose SHA256 pins are supplied by the accepted build/resource pipeline, not by the requesting player. It verifies those exact JSON bytes/pins, adopted source identity, exact source symbol/declaration/alias membership and backing digest/size before attaching the property. Proposed verified-context input is `original_presentation:{catalog_json,asset_manifest_json}`; expected pins belong to the trusted definition/build inputs. A caller cannot mutate JSON, retain its old provenance label and obtain the same binding. Missing trustworthy pins/definition key means no binding, not a name fallback.
- **Required immutable chain:** selected raw FrozenPackage/original inputs → verified context → controlled content-native-loader factory → immutable genuine definition property → existing Catalog → occurrence-time LogEvent copy → public DTO → frozen resource resolver. The factory derives packs/Catalog internally and accepts no second mutable packs array with matching labels. Arbitrary trusted Rust code retains its current authority, but browser/network callers cannot mint verified types or inject a separate Catalog.

Those tags cannot authorize this chain. Wait for/reuse the genuine shared verified factory; do not fake it under this presentation proposal or borrow R05's reserved axes.
- Same author capabilities: any installed extension admitted by the existing verification/trust policy can declare these bindings, assets and forms. No official-only list, hardcoded package namespace exemption, user-supplied absolute URL, generic keyword callback or replacement asset store. `resolve_active_asset_info` (`content-runtime/store.rs:854`) uses the **current active** version; an old occurrence must instead resolve its exact frozen owner/asset bytes using existing frozen package/store paths, never silently follow upgrade/disable/uninstall to another payload.
- **Hash boundary:** copied runtime properties/LogEvent payloads are intended presentation-only, but new package definition_id/assets/voice_assets change raw asset/package bytes and content_hash. `compute_logic_hash` (`content-schema/package/hashing.rs:35/:49`) hashes genuine skill/character rule fields; new voice_assets must be explicitly included only in compute_asset_hash (:401), with absent values legacy-neutral. package bytes/asset_hash/content lock still change, and native `content_lock_id` hashes pack.def.name/version (`extension.rs:196`), while server embeds LockedPackage there (`native.rs:294`). No `.content` canonical rewrite is proposed here.

## 3. DTO correction and public capability semantics
- Keep ONE optional `presentation?:PublicPresentationBatch` on existing S→C CommandOutcome / generic EngineEnvelope; preserve `events`/`public_event_codes` and their labels. Batch remains `{revision,status:"complete"|"incomplete"|"overflow",unavailable,occurrences}`. Occurrences are `{ordinal,event}`, public-order ordinal per sealed committed revision; raw private log indices never leave Rust. No cryptographic certificate, runtime-name identity bridge or caller-chosen span is a field.
- Typed events remain: `card_used {actor,targets,effective,voice}`, `card_responded {actor,effective,voice}`, `skill_activated {actor,skill,targets,voice}`, `damage_dealt {source,target,amount,nature}`, `damage_prevented {source,target,nature}`, `hp_recovered {actor,amount}`, `player_died {actor,killer,voice}`. Public player IDs are API1-based; Rust converts native0 once. targets=null means no committed public list, [] means authoritatively empty; no private hand/card IDs. Actual positive recovery/dealt amounts and prevented subtype are separate.
- `effective={kind:CardKind::key(),key:committed_public_use_name,nature}` uses actual validated use_as/nature; no transformed physical-face inference. `skill={definition:QualifiedDefinitionKey}` requires the actual public committed skill, not runtime Chinese name as identity. `voice=null | {role:QualifiedDefinitionKey,form:public_form_key|null,assets:BoundAudioAsset[]}` captures the exact public occurrence-time binding; runtime def/label may remain optional presentation diagnostics but never resolver authority. This shape is concrete proposed data and cannot be considered implemented/finally approved before the loader chain above exists.
- `unavailable=[{domain,reason}]` describes **public static build/content capabilities**, e.g. source_no_audio_discriminator, commit_boundary_unproved, verified_binding_missing; compute it before play from the admitted public content set/build support, independent of hidden activations. Public status=overflow derives only from serialized **legitimate public** occurrences; status=incomplete derives only from those static capabilities or explicit public baseline/history gaps. No “some hidden skill needed a missing binding” branch may add a flag/count or change status.
- Enforce paired-secret/no-secret equality of the entire metadata member, including absent/null/empty/status/unavailable/ordinal/overflow behavior; private rows do not count toward public limits or public ordinal. Silent secret activation is not turned into a named “unavailable” occurrence. Public missing resource declaration remains registered at capability/domain level; it does not exclude the corresponding I02 source from completion.

## 4. One shared Rust volatile committed-range lifecycle; no public raw-span getter
- Remove v1's `Engine::public_presentation_from(start)` and `NativeSession::public_presentation_json(start)` APIs entirely. Slice projection stays private inside existing `engine-native/src/presentation.rs`; callers cannot choose offsets, historical revisions or arbitrary logs and cannot stamp tentative rows with the current revision.
- Proposed ONE `Engine.presentation_range` volatile state, next to `log`, `segment_open`, `segment_checkpoint` (`engine.rs:155–170`): `Idle | Held{start,restored_prefix_unknown} | Sealed{start,end,revision} | Released{start,end,revision}`. It contains only indices into the existing host LogEvent vec and the already-committed revision, no event copies, second queue, event counter or receipt ledger. Fields/constructors are private; only Engine's existing mutation/rollback branches change it.
- Root begin seam: after submit's no-progress prevalidation, capture existing `log_mark` before apply_command (`commands.rs:133` parallel reveal / :159 normal) and enter Held{start:log_mark,false}. No-progress rejection must **not** begin/reset a held span. `finish_segment(work,log_mark)` reuses an existing Held start through resumes; existing trusted/debug roots using finish_segment must initialize from their actual entry log_mark, not infer a historical slice from current revision. Presentation never influences authorization/result/quotas.
- Root seal seam: immediately after the real state/revision commit in `finish_segment` Pending (:252–263) or Done (:298), close Held into Sealed using that final revision and current log.len(); the parallel RevealGeneral Pending return (:140–157) seals its own range at the same genuine commit. Yielded (:265) only retains Held. No adapter reproduces these branches from outcome strings, source_skill or a guessed last log cursor.
- Shared release/drain seam: trusted host calls parameterless `Engine::release_committed_presentation()`; it can only move an existing Sealed range to Released, never accept a range/payload/revision or release Held. `Engine::take_public_presentation()` projects and consumes **only Released**, otherwise returns None. `NativeSession::take_public_presentation_json()` wraps that same operation with no caller start. Projection is pure; take/release mutate only this volatile delivery state, not rule state. This is a plain additive JS binding, not a VM host query/opcode.
- **Local wrappers RELEASE ONLY:** NativeSession direct commands (`session.rs:463/:477/:514/:530`) and both auto_step submit/apply_plan branches (:594/:618) release only the range just sealed by their genuine commit; they never take/project/drain it. Existing `Result<String,String>`, `outcome_json` and WASM forwarding (`lib.rs:131–164`) remain unchanged, including auto_step.outcome as a nested JSON **string** (:605/:622). Rejected, no-progress, Suspended, done:true and planner-error branches release nothing. No presentation metadata is nested inside result/outcome_json.
- **One local consumer:** Worker `worker/nativeBackend.ts:809` nativeEnvelope (direct dispatch :889–955) feature-detects and calls parameterless `take_public_presentation_json()` exactly once synchronously while composing that just-returned command envelope, before another command; validate and place its owned batch at top-level `EngineEnvelope.presentation`. Rust desktop `native_envelope.rs:127` becomes mutable over NativeSession and does the same single take after `native_engine_host.rs:249–325` obtains the command string. NativeSession/WASM getter consumes only Released; second take returns None, Held/Sealed are never exportable. Old matched bundles lacking the method mean absent capability, with old strings untouched.
- **No stale/baseline drain:** Released is a one-response delivery latch within the existing single range state, bound to its committed revision and the immediately returning wrapper; it is not a second cached batch/queue/nonce. At each next command entry retire any unread prior Released before validation, preserving Held; a no-progress result cannot inherit/release it. Existing baseline response paths (observer/start/status/chooseGeneral/restore) do not call take and retire unread publication through the same Engine baseline-reset lifecycle; their composers must explicitly select baseline mode rather than treating any non-null result as drain permission. Internal view/legal/choice reads used inside a command composer do not reset its latch. Getter checks the current Released revision/latch, consumes once, and cannot make stale/baseline requests acquire a prior command batch. Adapter context authorizes which response consumes a release; Rust alone authorizes which range is committed.
- Server ownership is unchanged: same Engine release method **after durability.commit succeeds**, then ONE take into an owned DTO cloned for normal reply + all broadcasts (`room_native_actor.rs:545–603`, timeout :17–38). No next actor operation runs between sealing/releasing/draining. Store failure rolls back first and never exposes the staged batch.
- Only one staged range is retained; hosts must synchronously finish release/drain or rollback before the next command. Trusted misuse must not reject a legal game action or accumulate a ledger: retire an undelivered old sealed/released range at the next genuine operation, report a public delivery-gap diagnostic, and never merge old/new revisions. Actual product callers are required to prove this path unreachable. Getter repetition after a successful take is None; receiving duplicate transport copies still uses frontend admission dedup.

Do not blindly copy a Released latch into another live session; new product sessions/observer/source generations reset baseline.
