These root semantics are correct for their existing labels and should not be reinterpreted as finer events.

- `crates/engine-native/src/engine/views.rs:37` hides other/spectator unrevealed Kingdoms slots, but own/referee slots remain visible; skills collection (:69) is not a proof of public activation. Authorize public voice identity only from an actual non-null **revealed** general in the selected envelope, matched uniquely to catalog identity; own hidden knowledge is not public just because the UI can display it. Ambiguous dual generals/duplicate names require silence, not first-row selection. Do not expose hidden-general/skill names via resource fetches, errors or spectator audio.
- `crates/engine-native/src/engine/choice_source.rs:1` explicitly says owner-visible ask identity, not root certificate: only the uniquely matched OptionalGate source is returned (:28), as optional own `source_skill`. `views.rs:134` filters Own/Other; WASM `session.rs:444` only serializes it when present. ## Preferred minimum implementation (proposal only)
1. Add one battle-specific presentation owner beside BattleView, using existing selector/URL and native `<audio>`; keep protocol/schema/resource pipeline/versions unchanged. Touch `BattleView.vue` envelope+lifecycle integration, one small battle-audio module/component, and focused frontend tests only; Collection remains manual. Do not attach playback to general select/status refresh or raw store watchers.
2. First named slice: in a single live session, after a successful command envelope, require a continuous public baseline, exactly one code7, exactly one public seat alive→dead transition, stable identity and one unambiguous revealed general/catalog match with backed base death alias. Admit one deterministic declared base candidate (stable manifest order, no engine RNG); if any guard fails, record remaining unsupported case without fetching another actor's voice. This is complete only for that explicitly guarded slice, not all deaths or all I02.
3. Do synchronous admission before `presentationDelay`, rather than reading mutable store.lastEvents later. Keep a session-local revision/hash high-water mark with accepted-event ordinal, rejecting duplicate or stale admissions; same revision/hash result-null refreshes must not replay. Establish a silent baseline on start/join/restore/snapshot/reconnect; retain dedup across transient reconnect, create a new generation on new match/restore/room or observer/source changes. Never synthesize missed voices from a reconnect snapshot.
4. Revision/hash alone is not a universal event receipt: room generations and non-advancing ask changes exist, and gaps may be missed. For this death slice require adjacent accepted revision and one code7 as above; skip uncertain/gap/multiple death cases. WS retry with same state is consumed once even when rejected later; no audio for rejection. A revived player may die again on a later accepted revision and is not permanently suppressed by player ID.
5. Minimal lifecycle: one media element and bounded queue (e.g.8 pending candidates; explicit drop-oldest overload policy and no later replay of dropped events), one in-flight load, no full9652 preload. Changing mute/volume applies immediately; mute/volume0 discards queue and stops current media. Since no shared settings exist, add only the requested accessible battle mute/volume controls, not a generic settings framework or persistent format.
6. First gesture must be handled synchronously through a battle control; mounted async start (:599) cannot promise user activation. Catch play() rejection: NotAllowedError shows an accessible enable-audio action and discards stale queued voices; retry only future events after gesture. Audio is optional presentation and must never delay/throw into command handling.
7. Reuse native decoding; do not introduce WebAudio decodeAudioData or an unbounded decoded buffer cache. Epoch-check all async play/load outcomes; on close/pagehide/unmount/new match/restore/source change stop, pause, remove src/load to abandon old media, clear bounded queue, detach listeners and invalidate pending metadata responses. A late decoder completion must not resume old audio or clear the next source's error.
8. Extend Collection's path-scoped error/loadeddata pattern for manifest fetch,404,decode/unsupported format and play rejection; bound retained errors (current path/session), show missing mapping distinctly from transport/decode error, and never fallback to another role/hidden variant. Disconnect handlers `BattleView.vue:340`, reconnect :346 and `releaseMatchLocks:590` are required cancellation seams.
- Identity-free recovery is an independent smaller **effect** possible from code5 + canonical backed recover asset (one cue per code5 occurrence), but it is not a skill/card voice and cannot substitute for the requested named voice lifecycle. Damage code4 cannot safely play a “damage dealt” cue; card code3 cannot select card/sex/nature voice; source_skill cannot select activation voice. Keep these distinctions explicit.

## Missing discriminators and version boundary
- Full named coverage needs a public committed occurrence identity/sequence (or preserved existing receipt identity), event subtype (use/respond, dealt/prevented), authorized actor/target, effective card definition/nature for view-as, and actual committed skill identifier+owner with public visibility filtering. Death needs player and stable occurrence identity; variants need publicly authorized selection semantics. Current EngineEnvelope offers none of those event discriminators.
- Compatible option within current wire is the guarded death transition above (or neutral recovery effect); it cannot certify complete automatic voices. Existing Rust EventView/log access is not permission to broadcast all logs: it includes skill names, private-choice context and physical identifiers requiring a new explicit projection review.
- A frontend-only local adapter change may preserve existing receipt metadata internally where already available, but adding typed public payloads to WASM export/WS messages is a new contract, not “just relabel code3/4.” Do not invent an event kind or silently add fields. Fresh approval/design review must settle visibility, effective-card semantics, replay/dedup and compatibility first. Rule/archive bumps are not automatic for presentation-only derived logs (machine.rs:15 excludes logs from state/hash); actual persisted state/event/serialization or rule-semantic changes require rule/archive review. ABI/new export and WS/snapshot-schema changes require corresponding compatibility/version gate review. Existing330/105/758/WS6 stay untouched in this audit/proposed frontend slice.
