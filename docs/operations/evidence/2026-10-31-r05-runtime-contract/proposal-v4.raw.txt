## 1. 原始字节与最小字段，只有一条内容身份链

选择**保留并验证原始package.json字节**，不引入JSON规范化契约。content_hash唯一口径为`R/sign.rs:20 content_hash_hex(raw_bytes)`；logic_hash按包语义计算。空格、缩进、CRLF、键顺序或尾换行变动可使content_hash不同，即使解析对象与logic_hash相同。
沿用服务端现成形状：`FrozenPackage={binding:LockedPackage,package_json:String,assets:Map<relative_path,Vec<u8>>}`；package_json必须是已接受UTF-8原文的无损字符串，重新UTF-8编码逐字节相同；不得parse→stringify后充当原文。资产存原始字节，不能把解析后的cards/characters/pile对象当原资产。
浏览器NativeSaveSlot/NativeMatchContent候选**只增两个字段**：`canonical_locked_content:ContentLock`与`frozen_packages:FrozenPackage[]`；服务端NativeRoomState已有frozen_packages，只增`canonical_locked_content:ContentLock`。聚合锁与逐包binding互相完整匹配，不再增加hash/版本/原局状态字段。
浏览器现`contentLock:string[]`是启用包key列表，`lockSeed`是logic指纹拼串，`packsJson`是重序列化载荷；三者都不是Rust ContentLock。保留旧字段作兼容展示/旧档辨识，**不参与新路径身份授权**；新路径不可同时从packsJson另建一套内容，亦不能从当前安装记录给旧档补锁。
安装记录另增 `InstalledExtensionRecord.nativeFrozenVersions?:Record<version,FrozenPackage>`，使用现有slot/history/生命周期，不建第二包仓库。新安装/导入深层验证后才原子写该项；旧nativeVersions对象串不回填为“原始”。同slot同version字节不同即冲突拒绝并保原记录；新局必须选定一个精确安装副本。
`ExtensionsView→prepareImport`须在JSON.parse前保存局部`originalPackageJson=input`；候选prepare结果带该原文，`validateFrozenPackage`对同一原文UTF-8字节核身份/hash，成功后写`nativeFrozenVersions[version].package_json=originalPackageJson`。现prepareImport只保canonical=JSON.stringify(payload)，**不保原字节**，不能据旧注释推断有原包。
文件入口从ArrayBuffer严格UTF-8无损解码并保存原文（不剥BOM/换行、不替换非法字节）；粘贴文本按实际提交UTF-8为原文，不能将textarea重排后的文本冒充原文件。BOM不被包parser接受即拒绝。保留字节/核hash**不等于验签**，本地unsigned标记及既有签名信任policy不变。
`bundledNativePackages.ts`当前从JSON对象拼manifest+assets再stringify，不可能重建旧原文。新安装候选Vite `package.npack.json?raw`保完整原包文本，资产用原文件ArrayBuffer（可经既有?url分发）保全字节；Rust仍验同一原文与声明资产，旧编译对象不充输入。旧记录缺nativeFrozenVersions按§4重装；upgrade/rollback/activate/save caller同改。
安装单包用显式`validateFrozenPackage{packageJson,assets}`请求，沿现validator校验原文/资产并返回`FrozenPackage`（含Rust算binding），不在此强求完整依赖集。新增EngineClient.validateFrozenPackage并改ExtensionsView.deepValidate/import回调接返回值，prepareImport/commitImport只写验证返回原文副本；聚合锁在新局prepare产生，JS不复刻blake3。旧validatePackage不充冻结证明。

单个JSON导入无声明资产可用空assets；有声明资产必须一并取得相对路径原字节，否则拒装，不从任意URL/当前全局目录补。这里只补保留/验证，不改签名信任；旧validatePackage保持旧请求/结果形态，不能因旧reader忽略新参数而误验为完整冻结包。

## 2. 唯一规范匹配点与新局锁来源

在已有R锁/校验职责中提炼共享纯函数候选 `verify_locked_content(lock:&ContentLock,copies:&[FrozenPackage])->Result<VerifiedLockedContent,...>`；server冻结校验与W.installed_packs共同调用。只复用现有content_hash/ContentPackage.validate/资产hash/依赖排序，不另定义锁算法或R05 registry。
该匹配点按顺序核：①缺省/重复slot及字段类型拒绝；②`ContentLock::from_packages(lock.packages.clone())==lock`，原输入不是规范顺序也拒；③copy.bindings与lock.packages逐slot**全集相等**、不缺/不多；④hash原package_json.as_bytes并核binding.content_hash；⑤parse完整ContentPackage、validate/ABI，核namespace/package_id/version/logic_hash；⑥依赖版本/logic_hash与全集；⑦资产路径安全、声明集合和每份source_hash严格核对，未声明额外资产拒绝。
Validated结果只能由上述匹配点构造，持原锁/copies与依赖排序解析包；bridge不接未经验证替身。JS旧摘要检查可提前报错但不代此点。撤销仍在宿主原policy边界核slot/content_hash；无AssetManifest却提供资产不绕过声明验证。原byte hash在解析前核，不能先重序列化再hash。
**新局唯一采集时刻**：安装副本被选择后、Engine初始化/RNG前，Rust从选定copies验证出LockedPackage，调用现有`ContentLock::from_packages`生成本局原锁，再经过上述verify；将其结果与copies冻结进会话。标准局用`ContentLock::empty()`，不是空字符串lock_hash。
浏览器通过拟议Worker/IPC请求`prepareLockedContent{frozenPackagesJson}`调用共享Rust冻结入口，得到`{canonical_locked_content,frozen_packages}`；`prepareNativeMatchContent`改为await该结果，不从对象重算锁，BattleView只在start成功后存入matchContent。返回的copies原字节不变；start时再次核验避免异步间改包。
服务器只冻结本局选定slot及完整依赖闭包；可从当前安装锁取得对应LockedPackage，再`freeze_binding`读取并验证那些slot/version/bytes/assets。不要把current_lock中的无关启用包加入原局，也不能多次按package_id读取时悄悄换新版本；前后不符就失败，原局集合一经建立不再查active。

## 4. 精确空值／旧新context政策表（候选，未授权拒旧档）

以下是信封**字段形状的精确JSON示意**；`"<L0>"`代表Rust `ContentLock::empty().lock_hash`真实非空值，`"<L>"`/`"<P>"`代表经验证的非空锁/冻结包，非可直接使用的测试hash。缺字段、null、空对象、合法空集合必须区别，解析不得`unwrap_or([])`抹平。
| 保存字段JSON | 拟议处理（仍先过Archive/规则门） |
|---|---|
| `{}` | 仅可作为legacy标准候选：旧contentLock/pack_refs为空、packsJson缺或精确解析[]，snapshot必须真标准Catalog；有任意扩展证据则拒缺上下文，不生成原锁冒充 |
| `{"lockedContentJson":""}`、`{"lockedContentJson":"null"}` 或 `{"lockedContentJson":"{}"}`（新transport请求） | startLocked/restoreLocked拒空字符串、null对象或缺字段对象；不转标准，不退旧入口 |
| `{"canonical_locked_content":null,"frozen_packages":null}` 或 `{"canonical_locked_content":{},"frozen_packages":[]}` | 新字段已出现但无效，拒绝；不能按缺字段legacy分支接受 |
| `{"canonical_locked_content":{"packages":[],"lock_hash":"<L0>"},"frozen_packages":[]}` | 新标准局合法空context；Rust重算L0核对，Engine只走标准Catalog |
| `{"canonical_locked_content":{"packages":[],"lock_hash":""},"frozen_packages":[]}` | 拒错误empty hash；空数组不是允许空hash |
| `{"canonical_locked_content":"<L>","frozen_packages":["<P>"]}` | 类型错误，拒；ContentLock须为完整对象，frozen元素须为对象，不能传旧string[] |
| `{"contentLock":["ns/pkg"],"lockSeed":"old","packsJson":"[...]"}` | legacy扩展缺原锁/原字节，拒绝候选并保留原档；不得用该对象串/当前副本补出过去content_hash |
| `{"canonical_locked_content":{"packages":["<LockedPackage>"],"lock_hash":"<L>"},"frozen_packages":[]}` | 无论hash看似正确都因copy缺失或元素类型拒绝；任一新字段缺失亦拒 |
合法非空形状是`canonical_locked_content`原生ContentLock对象及`frozen_packages:[{binding:{namespace,package_id,version,logic_hash,content_hash},package_json,assets}]`的类型化值；`assets:{}`只在原包确无声明资产时接受，不能以`{}`跳过验证。
现server旧精确pack_refs可经freeze_reference补原副本，这是源码已有policy；本新路径**不默许迁移**。如要兼容缺聚合锁但有旧精确binding的记录，另行批准仅按那些原binding/refrozen bytes/资产验证的迁移，不从当前active或package_id选择替代；失败保留落盘记录与房号。
旧InstalledExtensionRecord只有nativeVersions或纯对象而无nativeFrozenVersions，不能声称已留原字节：新局提示重装原产物；从原保存档缺context恢复同样不能用重装变新hash救旧局。新信封/IPC/HTTP字段、strict unknown/type处理与legacy拒绝均需单独审批，不并入NC27。

## 5. 未运行的严格匹配验收计划及边界

1. 同包对象两份原文仅空白/CRLF不同：logic_hash相同、content_hash不同；分别构各自原锁可新建局，交叉恢复必须拒；parse/stringify不能让它们相等，同版安装不覆盖。
2. 标准缺context的legacy候选、新合法空锁、null、{}、空hash、单字段缺失、无manifest旧cards载荷逐项验；扩展档不能伪装标准，拒绝后原hex/锁/旧句柄不变。
3. 改namespace/slot/version/logic_hash/content_hash/lock_hash、重复/缺多包、换顺序不规范锁、依赖不完整或同名跨namespace逐项拒；校验必须发生在Engine初始化/RNG之前。
4. 原assets全部同字节恢复；缺/多/改一byte、声明路径越界或symlink回读/错误source_hash拒；保存后卸载/升级不影响原副本，撤销继续依原slot/content_hash拒。
5. Browser保存→Worker/WASM与Desktop IPC恢复逐字段同对象/选择/RNG；修改packsJson而新context没改不得改变引擎（新路径只用context），缺context不得走原packsJson兜底。
6. Server冻结→耐久存档→lobby/from_saved/restore_room_from_disk、WS Recover、WAL base回放及最终再restore均传同context；任一旁路用当前包替换、WAL原包不符拒且原文件/房号保留。
7. 安装文件与粘贴、内置raw分发、历史version回退、freeze时读取竞态、坏UTF-8/BOM不剥离、总大小限制、prepare成功后start前更换context的受控失败全部纳入定向caller测试；不新增性能/全包实验。
这些只补原12类中身份/恢复覆盖，不表示已新增测试或任何通过。v3的规则/ABI/Archive/投影/191异步迁移、实际331→实际332前置与单独申请R05增量保持；原局精确字节恢复不能由NC27 source_skill授权推导。
