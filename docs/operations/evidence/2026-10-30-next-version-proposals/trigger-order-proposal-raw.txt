## 1. Decision to approve

Adopt one bounded scheduler change: the existing serial resolution stack opens a **mandatory “choose the next skill” choice**, then runs the chosen skill through the existing confirmation/effect machinery. It does not ask for a whole permutation. Normal triggers use upstream player buckets and effective priority; First/Last triggers remain automatic. Choices use the existing `GameAction::Answer` and external `ResolveChoice` command shapes.

Recommended precise choices requiring approval:

1. **Ordering scope:** include normal-trigger player buckets (seat order before priority), remove `optional` as a scheduling priority, and defer filter evaluation until each dispatch step. This is necessary for the recommended upstream-compatible branch and is wider than merely replacing a final `def_id` tie-break. Decision 14 names same-player choice but does not expressly approve changing the cross-player primary key. **Ask for this scope explicitly.** If declined, implement no silently narrowed variant; return a revised local-choice proposal retaining a named cross-player difference.
2. **Choice representation:** keep `ChoiceKind::PickTag`, append the static prompt `trigger_order`, and add **`ChoiceOption::Skill(SkillDefId)`**. Approve this one option variant, its archive/hash/validation support, and its internal WASM JSON projection. Do not add a new ChoiceKind, parameterized prompt, VM opcode, network command, or Worker command. Why a new option is recommended: `Tag(u8)` cannot cover all `u16` skill definitions or an unbounded-by-256 same-player group. `Kind(u16)` is specifically a card-kind code and its archive decoder validates against card kinds. Neither may be silently repurposed, truncated, or padded with arbitrary limits. Pagination would add more machinery than the single typed option.
3. **Metadata and versions:** approve one unnumbered ADR becoming a formally allocated ADR only after approval; conditional rule **330→331**, archive **105**, native ABI **758**, WS **5**, Worker command envelopes unchanged. Approve the small package metadata additions described below, including their logic-hash validation and explicit rejection by incompatible readers. Do not treat decision 17's permission for J2 static prompts as permission for NC08. If timeout does not occupy 330 or another batch takes 331, reconfirm the actual NC08 rule number before changing it.
4. **Compatibility:** reject prior native ruleset archives/room recoveries rather than silently resume under the new ordering. Preserve originals, frozen packages, old locks, and the prior executable/replay path. No automatic archive migration in this batch.

## 3. Actual upstream semantics, including the branch boundaries

Primary source: [noname arrangeTrigger](/Users/ruyimg/Documents/Claude/sanguosha/archive/upstream/noname/apps/core/noname/library/element/content.ts:4017), [bucket construction](/Users/ruyimg/Documents/Claude/sanguosha/archive/upstream/noname/apps/core/noname/library/element/gameEvent.ts:504), [filterTrigger](/Users/ruyimg/Documents/Claude/sanguosha/archive/upstream/noname/apps/core/noname/library/index.js:10671), [priority construction](/Users/ruyimg/Documents/Claude/sanguosha/archive/upstream/noname/apps/core/noname/game/index.js:8842), [chooseControl](/Users/ruyimg/Documents/Claude/sanguosha/archive/upstream/noname/apps/core/noname/library/element/content.ts:8179), [chooseControl default](/Users/ruyimg/Documents/Claude/sanguosha/archive/upstream/noname/apps/core/noname/library/element/player.js:6894).

| Branch | Observed rule / required proposal behavior |
|---|---|
| Ordinary scheduling | Construct a bucket per player in seat order starting from current phase player (upstream has source/event-player fallbacks if no current phase). Each bucket is sorted by effective priority; normal priority does not globally outrank the earlier player's bucket. |
| First/Last | Separate global buckets before/after all normal player buckets; priority first, seat next; no ordering choice. They are timing flags, not strings inferred from event names. |
| Highest usable priority | Recompute usable candidates before every next skill using `filterTrigger`. Once proceeding at a lower priority, discard higher-priority entries that are no longer usable. A temporarily false same-priority filter can become true after a sibling runs. A one-time initial filter pass is not equivalent. |
| Silent/untranslated | In the highest usable priority group, **any** silent or missing-translation entry runs automatically first, even when other named entries exist. Then recompute. “有描述” here is truthiness of `lib.translate[skill]`, not `skill_info` or a localized tooltip existing. |
| Locked / optional | No locked/forced exclusion in ordering selection. Forced/locked, optional and mixed groups all qualify. Optional confirmation occurs **after** choosing that skill; selecting a skill is not consenting to activate it. |
| Candidate identity | Deduplicate skill names for the control list. Multiple indexed occurrences of one name alone do not open an order prompt. For a selected name, use its first eligible occurrence. Native currently has one queued instance per `(owner, def)` rather than upstream `getIndex` occurrences. |
| Iterative choice | For 3 distinct eligible names, ask for the next one, run it completely (including children), recheck and possibly ask again. Never commit a stale whole ordering. |
| Cancellation | `chooseControl` has no cancel control for ordering. If the choice event is interrupted and produces no result, current noname falls back to the first usable skill. Later skill activation can return `"cancelled"`; upstream then removes remaining indexed instances of that same skill in that player bucket. No cancellation of other skills or other owners. |
| Autoplay | `chooseControl` defaults to index 0 when no custom AI is set; online input uses its existing send path. Automatic decisions must be explicit recorded answers in native. Room deadline/托管 behavior belongs to the separately approved timeout implementation; NC08 introduces no timeout command. |
| Death/out/hidden/filterStop | Upstream allows `forceDie`/`forceOut`, hidden/invisible skills and skill-specific limits through `filterTrigger`; `filterStop` can stop the window. Native currently always excludes dead owners, and lacks several of these representations. These differences must stay named; adding B cannot establish unconditional upstream equivalence. |

Use current noname as the scheduler tie-resolution oracle and record these liuli differences per affected case. ## 4. Proposed ADR content: one implementation, exact state transition

**Title:** Player choice of the next simultaneously eligible trigger in the native resolution scheduler.

**Context/problem:** Current source plans a global priority/optional/seat/definition queue. For two equal-priority VM skills of one owner, users can confirm each skill but cannot choose their order. Registration order changes the outcome. Determinism does not require removing interaction because accepted answers already form an ordered, durable command stream.

**Decision:** retain the kernel stack, frames, queues, parks, machine snapshots and the single choice channel. Introduce one small kernel `TriggerOrder` machine and the one typed option above. Reuse `OptionalGate` for activation confirmation and all existing host/VM effect machines.

**Metadata contract (proposed, requires approval):**

- Add `order_selectable: bool` to native `TriggerMeta`. Its source meaning is exactly `!silent && bool(lib.translate[skill])`. It does not mean optional/unlocked. Existing `timing` and `priority` remain the other ordering metadata.
- Carry `timing` (Normal default), effective `priority` (0 default), and `order_selectable` (true default) in `PackageTriggerEntry`; ordinary named authored DSL triggers keep those defaults. There is no need to invent a new DSL primitive or grammar for the existing default case. Imported nondefault triggers must populate these explicit index fields; the compiler and any merge/rebuild path must preserve or regenerate them, not overwrite them with defaults. Unknown timing and malformed priority are load errors.
- For migrated upstream content, generate `order_selectable` from the pinned source's truthy **name translation**, not runtime locale, current UI assets, `locked`, or `_info`. For original DSL authors, a named skill is selectable by default; a deliberately automatic trigger may explicitly set metadata false. No runtime dependency on JS or upstream directories.
- The fields alter rules. Include nondefault metadata in a domain-marked, canonically delimited segment of `ContentPackage::compute_logic_hash`; defaults may be hash-neutral following existing additive metadata patterns, provided a reader that ignores a nondefault field demonstrably refuses its hash. Include equivalent metadata in native pack identity/content-lock construction where direct `ExtensionPack` bypasses npack. Current `content_lock_id` hashes only pack name/version: do not assume that alone authenticates new metadata. Give modified packs new immutable versions and logic hashes; validate frozen payloads at formal imports and restoration.
- Keep package format 1/content schema 3 only if additive defaults plus the actual old-reader hash/version tests prove unambiguous rejection of meaningful nondefault metadata; **no schema-version bump is preauthorized**. If that proof fails, stop for a concrete schema/version amendment. ABI 758 stays possible because this is scheduler/package metadata, not a VM instruction/host-operation change.
- Audit and populate metadata for actual native host/standard trigger constructors as well as VM declarations. A blanket `order_selectable = optional` or blanket “every host skill has a label” is wrong. Display translations remain presentation data; the bool is the locked rule decision and must not change when language changes.

**Execution algorithm (no second scheduler/runtime):**

1. At stage entry, collect subscribed `(owner, def)` entries in the existing `Frame.queue`. Preserve the current event/stage mapping, including the existing PhaseBegin VM-before/host-after split. Do not drop entries just because their behavioral filter is false at initial collection; later sibling effects can enable them. Disabled/dead/native-unavailable instances are rechecked at dispatch. Current native alive-only semantics stay a named difference unless separately modeled.
2. Sort into First → normal player buckets in `seat_steps_from(turn.current, owner)` order → Last. First/Last: effective priority descending then seat then stable def fallback. Normal: seat first then effective priority descending then stable def fallback. The `optional` discriminator no longer ranks forced ahead of optional. Keep the serialized queue/order tuple representation if it can express these branch-specific keys; document each component and validate it. Do not leave an ignored/tamperable old optional byte that later code treats as authoritative.
3. For the active bucket, derive currently usable entries with a shared native eligibility check: instance exists/enabled; owner availability under current native rules; matching trigger; once-per-turn still available; current event payload; current behavior filter. Recompute after every child effect, confirmation decline, or nested machine return. Find the highest usable priority and discard skipped higher priorities, mirroring upstream's no-return-to-higher-priority behavior. If no usable entry remains, finish this bucket and continue in seat order. Do not discard a temporarily false sibling of the current priority until the priority/bucket moves on.
4. First/Last choose the first eligible entry automatically. Normal group: if any entry has `order_selectable=false`, dispatch the first such entry automatically; otherwise deduplicate by stable skill identity and dispatch automatically for 0/1 distinct names. For 2+ names, park `TriggerOrder { frame, owner, candidates, asked }` in existing `Slot::Trigger { frame }`. Candidates are a deterministic ordered vector of `SkillDefId`, unique and from this same active priority group. Open `ChoiceSpec { kind: PickTag, prompt: "trigger_order", options: candidates.map(Skill), min: 1, max: 1, allow_cancel: false }` through `Flow::WaitChoice`. The frame retains all unconsumed entries.
5. `Answer` is validated by the current choice/actor/revision/dedup path. The ordering machine consumes the one typed selected def and rechecks its eligibility and frame binding. It removes **only** the selected queue occurrence, starts the existing shared selected-trigger path, and finishes its own park. Optional selected skills enter `OptionalGate`; forced skills start directly. There is no early limit consumption or `SkillTriggered` log just from choosing an order. Once usage/log emission must remain at actual skill activation. Recheck optional eligibility on confirmation as well, before consuming the limit or starting the behavior.
6. Child frames/effect choices suspend and return through existing park depth behavior. Once the selected skill finishes or is declined, dispatch rebuilds the next group. For an owner death, disabled skill, changed filter or changed frame context while a choice is open (notably permitted RevealGeneral input), never run the stale candidate. If the submitted skill is now ineligible, complete that ordering continuation without an effect and let dispatch recompute; if the published choice itself needs replacement, issue a **new** choice id. Never retarget an existing token silently. Malformed/wrong actor/stale client answers remain rejected with no mutation; authoritative intervening inputs are separate accepted commands.
7. No ordinary client cancel exists for `trigger_order`. Empty selection and multiple selections are rejected. A skill's later optional confirmation may be declined and consumes that queued attempt only. Native's one-occurrence-per-owner/def queue makes upstream duplicate-index cancellation vacuous today. Do not claim `getIndex` support by storing a list of names; actual indexed trigger support remains a named gap and blocks equivalence for such cases.
8. For AI/default/manual takeover, use an explicit existing Answer selecting the first current candidate, consistent with upstream index-0 fallback. Do not consume RuleRng for ordering. The timeout actor selects through this path after its separate batch lands; do not add another clock, policy engine or synthetic command. A richer strategic AI is unnecessary for this correction. The no-result upstream interruption fallback is an internal automatic-answer concern, not permission for empty client selection.

**Proposed snapshot, not an opaque closure:** `MachineSnapshot::TriggerOrder { frame: EventId, owner: PlayerId, candidates: Vec<SkillDefId>, asked: bool }`. When selection is consumed, the chosen existing skill/OptionalGate park replaces this machine; no duplicated inner skill state or separate stored whole permutation is needed. Frame event/priority are validated from the bound frame and queue, not an independent second event copy. The machine's `fork`, `snapshot`, restore and derived ExpectedAsk must agree. While asked, exactly one parked machine must own the current choice.

**Consequences:** same commands/versions/content/RNG produce the same state. Additional player answers change revision, choice IDs, budget expenditure, event trace and intermediate hashes. Different answers can legitimately change later RNG consumption through different skill effects; asking for order itself uses no RNG. First/Last, ineligible, mixed forced/optional and silent cases are explicit, not accidental side effects of enum ordering.

**Rejected implementation shortcuts:** final-key-only replacement; optional-only groups; Tag casts/truncation; abusing card-kind codes; whole-permutation choice; client-side queue sorting; using current language/translation assets as a rule filter; reconstructing pending choices from live globals after load; adding a generalized runtime/ECS/extension framework.

## 6. Archive 105, canonical hash, commands, retry, WAL

Archive 105 is a versioned explicit-tag codec, not a universal “append bytes anywhere” mechanism. Current resolution encoding stores frames/queues, parks/machines, open choice, pending answer and budget sequentially. Existing B7/J1 appended fields inside the known Rvm payload and rely on rule-version refusal; they do not provide an arbitrary, length-delimited Frame/Resolution tail reader.

Recommended reuse: leave `Frame`, `ResolutionSnapshot`, existing Rvm and OptionalGate layouts intact. Add one **fresh** MachineSnapshot tag for TriggerOrder and one **fresh** ChoiceOption tag for Skill; allocate both only after reading the integrated J2/timeout codecs. Reuse existing `OpenChoice` fields and PickTag. Append `trigger_order` to `KNOWN_PROMPTS`; its archive encoding is currently a UTF-8 string resolved by that whitelist, not a prompt ordinal. Preserve append-only ordering nevertheless; do not move prior registrations.

This can retain archive105 because no old payload tag is reinterpreted: new binaries parse new rule331 snapshots; old binaries reject unknown tags or the ruleset; old rule snapshots are rejected by current ruleset gates. It is **not** a guarantee that old binaries can decode new archives or that old rule105 archives can resume under 331. Test both generic snapshots and extension-derived ruleset versions (the latter combine the standard version and content lock, not just the integer 331). If implementation needs to alter an existing payload ambiguously, do not raise to 106 silently: stop with the exact failing codec/restore case and ask for format approval.

Canonical state evidence must distinguish:

- Queue contents/order and active band/seat/priority; parked TriggerOrder identity and ordered candidate vector; open choice observer/id/kind/prompt/options/min/max/cancel; pending answer; selected skill/OptionalGate park; event payload; event/choice ID counters; semantic skill storage/once/hits; RuleRng and nested child frame state; budget/segment checkpoint state.
- `canonical_hash` currently includes most queue keys and semantic state, while machine snapshots use an explicit manual match. Updating only open_choice hashing is insufficient. A one-field mutation in each new semantic field must either change the canonical hash or be refused as noncanonical. Check `q.order.4` versus `q.def`: reject contradictory redundant fields or hash any independently authoritative component rather than leave a hidden semantic alias.
- `auth_generation`/credential rotation on restore and transient fault/log bookkeeping must be interpreted under the existing documented exclusion policy, not made equal by discarding semantic resolution fields. Full state comparisons may normalize documented session credential changes, not queue/RNG/limits.

Command/retry effects: opening an order window commits a pending outcome; each accepted Answer consumes a dedup high-water mark and advances revision under the current engine contract. Rejecting wrong actor, old revision/id, duplicate selection, empty mandatory answer, unknown Skill or extra selections does not mutate rules state, consume RNG, emit effects, or consume a rejected dedup key. Room same-idempotency-key retries return their original receipt; timeout/manual races still serialize through the room actor. Wrong-body same-key retry follows the existing conflict policy. Never recreate a choice under the same id with different token meanings.

Persistence effects: checkpoint before a choice, persist while pending, accept Answer, durable commit before broadcast, restart and replay from snapshot+accepted actions. The durable state must include the order continuation and new typed Answer; existing room journal/checksum formats need no predicted field change, but their serialization actually contains the new enum variant and must be checked. Test failure before durable commit and uncertain/after-rename recovery with the current `RoomDurability` rollback/journal logic; a logical Answer must not run twice. A timeout Answer must replay from the recorded choice, not call the AI again. No new WAL command, clock field or journal schema is proposed by NC08.

Old data trajectory: retain original archive bytes and frozen npack/locks; same-rule new archive105 restores; older native rulesets explicitly refuse with version/unknown-tag/codec error as appropriate; wrong content lock or missing package refuses. Preserve ability to open/replay old artifacts with a matching retained executable/content set. A future migration would need a separately approved offline converter or replay through the old binary to an export boundary with tested semantic mapping; rewriting only the version/checksum is forbidden. A pending old def-ordered trigger window cannot be transparently converted to an already-answered player-choice window because the historical command stream contains no such choice.
