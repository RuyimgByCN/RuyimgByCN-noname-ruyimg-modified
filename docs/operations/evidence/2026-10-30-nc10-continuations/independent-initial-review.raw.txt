- **Finding: P2 — A valid nonzero VM card reference can be remapped into the VM’s no-card sentinel.**

  Location: [remap.rs:32](/var/folders/b5/2mh_j5tj7m71xhcjsk2z1t4c0000gn/T/noname-nc10-ai-113i2ib5/worktree/crates/engine-native/src/ai/remap.rs:32), with allocation at [redact.rs:118](/var/folders/b5/2mh_j5tj7m71xhcjsk2z1t4c0000gn/T/noname-nc10-ai-113i2ib5/worktree/crates/engine-native/src/ai/redact.rs:118).

  The visitor protects an **incoming** zero, but permits `map(nonzero)` to produce zero. Native physical CardId zero participates in the unknown pool. The VM commit layer interprets zero as no card: `rvm_ops.rs:492` skips `StoreEventCardInSkillPile`, and `rvm_ops.rs:650` skips it in `MoveCards`.

  A source-level counterexample is a real commit-pause queue containing `DiscardHandEquipCount` followed by `StoreEventCardInSkillPile(card=C)`, with `C != 0` in an unknown zone and the physical permutation assigning `C → 0`. The new helper rewrites both the physical card and queued reference to zero. On resume, the store effect returns early instead of moving the remapped physical card. This changes continuation behavior despite retaining valid physical ownership.

  This queue is expressible through the existing VM effect decoder and admitted by `accept_effect`; `requires_conservative_redaction` permits `Rvm { paused: None, commit_pick: Some(..) }`. It is therefore a current helper defect, not a hypothetical future opcode. The new live commit test queues discard/draw and does not exercise a pending card-bearing effect.

  **Smallest bounded fix:** retain conservative helper handling for commit-paused Rvm states until their card mapping preserves the VM sentinel contract, and add a focused `nonzero → native zero` pending-effect regression. Do not change the authoritative ID/ABI contract incidentally. Severity is P2 because ordinary planner entry at this prompt returns the public leaf before invoking redaction; I have not established an authoritative-plan failure through this defect.

- **Finding: P2 — Remapping another seat’s filtered response options can create a clone that fails choice restoration.**

  Location: [remap.rs:225](/var/folders/b5/2mh_j5tj7m71xhcjsk2z1t4c0000gn/T/noname-nc10-ai-113i2ib5/worktree/crates/engine-native/src/ai/remap.rs:225), enabled by the seat-independent continuation gate at `ai/redact.rs:23`.

  The helper remaps existing `ChoiceOption::Card` entries mechanically. Such a permutation preserves physical identity relationships but does not preserve catalog properties used to derive a choice. For example, [snap/asks.rs:147](/var/folders/b5/2mh_j5tj7m71xhcjsk2z1t4c0000gn/T/noname-nc10-ai-113i2ib5/worktree/crates/engine-native-kernel/src/snap/asks.rs:147) derives an ordinary `respond_shan` choice by filtering the responder’s hand for Shan.

  Counterexample: seat 0 has opened a normal Sha response for seat 1; call `redact_opponent_hands` for seat 0. Seat 1’s hand is now unknown and reassigned. If an original Shan `C` maps to a non-Shan `Y`, the stored choice becomes `Pass, Card(Y), …`, whereas `active_ask` excludes `Y` and derives options from the sampled hand’s actual Shans. `Engine::restore` compares the ordered option lists and returns `OpenChoiceMismatch`.

  This can be constructed without relying on a lucky seed: give the responder the remaining unknown cards, then order the original hand so a Shan occupies the allocation position receiving a known non-Shan from the deterministic pool. The initial response state is valid; the new mapping makes its stored options disagree with the shared derivation.

  The old suspended-Duel gate required `choice.observer == seat`; other such windows retained their hands. The patch removes that restriction, making this helper regression reachable. The added response tests redact for the actual choice observer, whose own hand remains fixed, so they do not cover it.

  **Smallest bounded fix:** keep conservative handling for a current choice belonging to another seat, or rederive the sampled choice through the existing shared ask machinery where supported. Add a non-observer response-window restore regression. Severity is P2: the ordinary active-observer planner path avoids this case, and I did not establish a new authoritative-plan rejection caused by it.
