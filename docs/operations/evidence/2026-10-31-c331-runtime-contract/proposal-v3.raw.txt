A boundary has a monotonic EventId, actual actor and exact phase/window. Expire matching records installed before that boundary (`installed_at < boundary.id`) in one pre-collection transaction; disabled grants still expire, and grants added during that boundary are not swept again. Actor matching uses the boundary actor, not current-turn coincidence. An idempotent renewal of one source key replaces only its expiry and keeps its provider ID. The actual addTempSkill API uses one canonical `(owner,genuine skill)` temporary slot across callers; its latest qualifying renewal updates that record/issuer rather than creating a second cause. Independently keyed temporary/additional providers remain distinct. In particular Gwent renewal and Jiguanfeng’s add-only-if-absent refer to the same source Fengyin slot. Capture installed_at from the live grant transition, not an older logical root; a NO_FRAME trusted grant reserves a checked event-sequence value atomically. addTempSkill semantics do not create a temporary overlay when an effective permanent provider already supplies that skill (`player.js11960–11970`); a later independent permanent grant nevertheless survives any existing temporary record’s expiry.

`GrantIssuer={Skill(QualifiedSkillRef),BuiltinMode{mode:GameModeKind,site:ModeGrantSite},TrustedHost(HostGrantSite)}`; mode sites are limited to actual initialization/Boss-reinit/Versus-substitution paths, host sites to existing bootstrap/debug explicit grants. `GrantSourceKey=(issuer,declared logical grant key)` resolves through the locked invoking declaration or the fixed existing mode/host entry, never arbitrary caller strings, repository paths or a new producer registry. Additional Core Qianlong uses its genuine qualified mbqianlong source key; replacement affects only that keyed set. A new mode/additional writer outside these actual entry paths is pending, not implicitly authorized.
