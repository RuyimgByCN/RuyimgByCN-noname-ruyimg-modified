**1 — Canonical damage quantity, ordered source windows and repetition.** Actual retained `kernel/damage.rs` keeps frame `d.amount` while modifying a local amount, subtracts armor at254/273, returns on jidong/chengxin without setting frame prevention, and emits Dying inside commit987. Thus neither current frame amount nor `amount==0||prevented` certifies a source damage outcome. Replace that contract, not just the repeat formula.

The proposed native Rust/API change is `DamageData.amount: i32`, meaning canonical mutable **source event.num**, plus `settlement: DamageSettlement{committed_damage:Option<u32>,hp_loss:u32,outcome:DamageOutcome,notrigger:bool,progress:DamageProgress}`. `DamageOutcome={Running,Cancelled,ReplacedByLoseHp,Zero,Completed}`; committed_damage is a positive submission receipt, not permission for any later window. `DamageProgress` is the sole persisted next-step/window/stop state; no duplicate authoritative amount in a machine or armor-local variable. This and the existing damage hash/codec/API consumers are explicitly new C approval scope.

| Transition / stored progress | Quantity, stop and child-completion rule |
|---|---|
| `Before → Begin → Begin1 → Begin2 → Begin3 → Begin4` | These are distinct adopted damageBefore/damageBegin/damageBegin1–4 windows. Root amount is checked signed arithmetic; existing amount modifiers/redirect/cancel effects write the actual root before the next candidate. No local shadow amount survives a yield. Before/Begin generic windows follow GameEvent.loop; Begin1–4 follow content.ts12038–12059. |
| `CheckStop(next_window)` | Before collecting a window, re-filtering order choices, confirming, or starting the next candidate, clear root.source if actually dead; sample current root amount/outcome. Cancel/replacement suppress normal later windows. If running amount≤0, store Zero and `ZeroPending` before scheduling exactly one damageZero child; after its subtree store `Stopped`. No repeated Zero, no old source restored later. |
| `SubmitHp` | After all Begin modifiers, amount>0 and not cancelled/replaced: atomically set committed_damage=Some(amount as u32); separately compute armor/actual HP-loss quantity, commit armor/HP once, set `HpCommitted`. Armor never subtracts root amount. Infinite HP or full armor can yield Some(n) with hp_loss0. `notrigger` suppresses trigger windows independently from this receipt. |
| `TargetDamage` | After HP/changeHp children finish, open actual target `damage` if positive committed source damage and triggers allowed. This is before Dying, not the old merged native Damage after-window. |
| `DyingPending → DyingDone` | If the current target is alive and hp≤0 and not already dying, emit one real Dying child, persist the continuation, and await its entire rescue/death subtree. Re-read target/source after it; target death alone does not invalidate a still-live source’s later source window. |
| `Source → End → After → Done` | Open adopted damageSource, then generic damageEnd, then damageAfter, with fresh stop/source checks and each subtree fully complete before advancing. Source dying during Source remains None in End/After. A positive receipt alone cannot override cancellation, notrigger or a later num≤0 stop. |
| `Cancelled` / `ReplacedByLoseHp` | Set outcome before emitting cancellation or LoseHp child; wait for that child, then terminate normal damage windows. Jueqing/Wuxin replacement is not a successful damage receipt. A source-prescribed Cancelled event is separate from Zero; do not emit both by default. |

Core source evidence: content.ts12115–12161 records damage, changes HP, runs target damage, then enters dying;12223–12225 runs Source; GameEvent.loop247–289 supplies Before/Begin/End/After. player.js8991–9009 clears dead source and stops nonpositive num. changeHp12330–12341 absorbs armor from its own HP delta while preserving parent damage.num. Liuli’s adopted damage/stop bodies agree on these named windows; source-specific body differences remain registered.

Move every affected inline damage cancellation, amount modifier and post-damage callback to its qualified declaration/window or the corresponding resumable intrinsic transition. In particular, preexisting early returns become typed Cancelled/Replaced outcomes, Begin modifiers no longer run after armor, and hp-loss-only effects do not read event.num accidentally. Source/stat/log consumers select the documented source quantity or hp_loss explicitly. Existing chain damage creates independent roots after the source-prescribed parent completion; never push a sibling chain child above an uncompleted Dying child because of LIFO insertion.

Use **one existing frame stack**: a damage root is advanced by new tagged `DamageFlow{root:EventId}`; progress and settlement live only in root data. It emits one appended `DamageWindow{root:EventId,window:DamageWindowKind}` child at a time; that child uses its ordinary `Frame.queue`, then pops. `DamageWindowKind` covers the table’s named trigger windows, Zero and source-prescribed Cancelled. Window eligibility/filter/start resolve the checked root ID, never stack.last guessing; restore rejects wrong root/type/window ancestry and double HpCommitted/ZeroPending execution. No second queue or scheduler is introduced.

Freeze each numeric repeat count when **that actual source window is collected**, after its stop check: snapshot `max(0,root.amount)` for DamageAmount; DamageAmountElseOne uses that number for its damage binding and1 for its non-damage binding. Preserve that count across choices/children/restores; subsequent num changes can stop/re-filter remaining occurrences but do not re-expand them. Each occurrence executes one source unit; the new Qianlong child must not multiply by damage again. Bound counters by checked u32 and execution by existing step/fuel budget, with O(owned matching definitions) counter storage and no count-sized allocation.

ABI proof/limit: existing `HostContext.event_amount:u32` is loaded by HOST_EVENT_AMOUNT as `as i32` (`rule-vm/src/vm.rs348–349`). Replace **both** with a common `effective_window(frame)` and `subscribes(resolved_binding,effective_window)` based only on source window, target phase and genuine declaration. Collector, dynamic additions, order-choice refresh, optional gate and restore use that same function; backend type never selects timing.

|---|---|

At begin:true, construct **one** BeforeTriggers queue containing all eligible VM and host declarations with their own tuple, run it to completion, then commit phase entry; no second host AfterTriggers collection for that same window. At begin:false, finish the phase body, collect one shared completion queue, then advance the phase. Serialize/resume each queue’s actual frame/window and recompute membership against the same resolved bindings; reject an archive that moves a host/VM entry into a different window.

Expose the source entry’s `turn.phase` as the target phase before collecting its entry queue, without running entry effects; keep `turn.current` as the real whole-turn actor, and use frame.player for an inserted phase’s actual actor. Store that transition before yielding so restored predicates see the same phase; metadata’s AtPhase predicate must read the bound phase frame, not a stale global phase or an inferred owner match.

Unchanged old schema3/4 byte identities do not freeze C’s known-wrong host-after/VM-before execution split: rule331 is the proposed corrected execution boundary. Existing declarations keep their documented Core semantic; unsupported Prepare declarations continue to reject. This work does **not** introduce Prepare, R05 Draw phases/191 asyncDraw migration, Tiqi/Baoshu/Dcbihuo or a dependency on R05. **3 — Parent edges, provider lifetime and no-slot hidden grants.** Listing siblings is withdrawn as a parent-lifetime representation. Add to the proposed schema5 `PackageSkillEntry.group_children: Vec<u32>=[]` referencing real dependency-resolved logical child identities; source group edges only, not all subSkill definitions. Lock-resolved `Catalog.group_children` is the immutable relation, not a new global/source registry. Validate referenced declarations, duplicates/cycles and genuine child names; no runtime path/commit/namespace switch selects semantics.

Actual edges: Kunlunjing→kunlunjing1/2; selected Liuli mbqianlong→mbqianlong_1/_2/_3; noname mbqianlong→begin/add/die; Xuanying→sha/use only. Source27’s accepted initial/admission semantics and C6’s no-damage grant remain intact. General/equip arrays name root providers; independent explicit child grants are allowed, but are independent providers, not inferred edges. Sharing one child between parents is legal; removing one parent must not remove another root’s grant or reset the shared logical skill’s counters/storage.

Add typed `GameStateCore.skill_grants: BTreeMap<(PlayerId,SkillDefId),BTreeSet<GrantProvider>>`, and `next_grant_id:u32` for non-derivable extra grants. `GrantProvider={General{slot:u8,general:u16},Equipment{card:CardId},Global{def:SkillDefId},Extra{id:u32,issuer:QualifiedSkillRef,visibility:GrantVisibility,reveal:RevealBinding},Group{parent:SkillDefId}}`; QualifiedSkillRef is the already locked package/logical identity, not raw source paths. `Group(parent)` means that the parent is currently owned through at least one provider; its visibility is derived recursively from those providers, not cached as a public child override. General/equipment/global providers are reconstructed from authoritative state and checked against this map; Extra IDs are monotonic checked counters and restored exactly.

Grant/remove transaction: add/delete exactly the matching provider, recompute the finite acyclic group closure, create a SkillInstance only on zero→nonzero effective providers, remove only on nonzero→zero; retain one instance, once_used and content storage on nonzero→nonzero. Repeated idempotent grant of an identical provider does not duplicate it; distinct Extra providers retain separate IDs. Explicit remove-all/clear/uninit applies its documented source scope and cascades the owned group closure; ordinary disable preserves providers and underlying enabled, and ordinary death follows the source-specific lifetime table rather than pretending every provider was removed. Do not reset an already-owned child when assembling a second general or replacement equipment.

Crucially, this relation represents **owned group children**, not all effects caused by a skill. Independently applied/helper effects receive their own Extra/effect provider and lifetime; they do not become Group(caster-parent). R05’s target roles may outlive the caster/parent and remain governed by R05’s approved role table. This amendment does not migrate those roles or pre-empt their storage design.

Hash and restore the sorted exact provider sets, next_grant_id, issuer identity and visibility/reveal binding with domain `native-skill-grants/1`, plus existing skill instance counters/storage without copying them into providers. Limits: players/defs/cards use actual catalog bounds; propose a fixed `MAX_GRANT_PROVIDER_RECORDS=65_535` across the snapshot, checked before inserting/decoding, while monotonic Extra IDs fit checked u32; command step/fuel budget also applies. Exceeding the record cap is a controlled error, never truncation, and does not mark an unsupported source complete. Enforce the cap before allocation, never derive a huge Vec from the ID counter. Validate no dangling group edges/providers, exact general/card ownership and closure↔SkillInstance membership. Remove precise providers on unequip/general replacement/extra revoke; retire only now-unowned instances, and reject forged issuer/slot/card/Extra IDs.

For a concealed general provider, reuse the real slot reveal action and existing ChoiceOption::Tag(slot); derive candidate slots from this provider set, not just every general listing the same name. For `Extra` with no general slot, `RevealBinding={None,TriggerHook{before:Option<u32>,after:Option<u32>},ConfirmPublic}` names validated genuine hook handlers or a concrete public reveal action. AskReveal without a real slot or non-None reveal binding **rejects at load/grant**. It must never invent slot0, use a default-true hook, or merely flip enabled.

No-slot execution uses new tagged `ExtraReveal{owner,def,provider_id,stage:BeforeHook/Ask/Publish/AfterHook/Run/Done}`. TriggerHook runs declared children through normal frames; actual suppression/cancel terminates activation. ConfirmPublic uses an existing Confirm choice, then publishes that Extra provider’s logical skill identity; it changes visibility to Public for that provider only, then runs the declared after hook/effect. Invisible grants use the actual source invisible hook binding, not automatically the general reveal path. RunHidden does not publish. Any public provider already supplying the skill avoids an unnecessary concealment prompt; loss of that public provider leaves surviving hidden providers hidden.

Public compatibility is not silently assumed: retained `PlayerCellView`/`SeatView` have alive, generals and skills but no out; native build_view currently lists all enabled skills and would leak Extra hidden identities. Filter skill names by effective provider visibility (owner/trusted Referee may see authorized hidden identities; other seats/spectators/AI receive their existing permitted views), and make SkillView.enabled reflect effective enablement without exposing private provider IDs. Existing Own/Other choice projection and token/label_key options can carry reveal prompts; no new ChoiceKind, option type or message variant is needed. Source hidden hooks themselves remain to be implemented/tested, not certified by this schema.

Keep alive and out distinct. Proposed public `PlayerCellView.out:bool` and additive `SeatView.out:bool` use serde default=false and omit false; native JSON emits out consistently. This is an explicit projection-contract addition in the approval scope, not a reserved mark/skill or alive=false disguise. Update native/WASM/server/web/AI consumers together; old JSON readers may ignore the optional field and old seat-view JSON defaults false, but an unupdated client’s rendering is not C acceptance. WS6 is retained only after additive-reader/decoder and current-client behavior checks confirm this introduces no new required envelope/message semantics; otherwise stop for the precise protocol decision, do not borrow R05 WS7 automatically.

**4 — Exact skill-boundary admission, cost and continuation order.** `game.createTrigger` builds a non-triggering outer event named trigger (`game/index.js5989–6008`); `content.ts4150–4178` runs a named cost event when present,4233–4243 cancels on failed result,4271–4285 logs and only then creates the genuine skill content event. GameEvent.loop247–289 supplies that **inner event’s** Before/Begin, body, End/After. Cost `_cost` events are separate events; the outer trigger is not the skill-name Before window.

The source order is `source eligibility/concealment → direct/forced admission OR actual optional confirmation/cost → successful cost result → logSkill children → create named skill event → SkillBefore → SkillBegin → body/children → SkillEnd → SkillAfter`. Source27’s actual initial/confirmation behavior is preserved: do not move a named Before outside OptionalGate, do not advertise the outer wrapper’s name as an unknown inner’s identity, and do not infer Before from a log line. Add Begin/End to the proposed SkillBoundary enum because GameEvent.loop creates them too; emit only genuine declared windows, no fabricated cost aliases.

Preferred placement is **inside** admission: keep old OptionalGate layouts and exact ask derivation; on accepted confirmation, construct tagged `SkillInvocation` as its inner, carrying the actual resolved owner/logical child identity and execution binding. Forced/direct handlers create the same admitted inner without the confirmation gate. Host bodies with an existing internal confirm must explicitly expose that real admission stage; do not wrap a second confirm around it. An unresolved inner identity receives no SkillBoundary subscription until its genuine declaration is known; it cannot borrow an outer SkillDef name by guess.

`SkillInvocation{owner:PlayerId,def:SkillDefId,binding:ExecutionBinding,stage:InvocationStage,cost_result:Option<CostResult>,inner:Option<Box<MachineSnapshot>>}`; `InvocationStage={Cost,LogChildren,Before,Begin,Body,End,After,Done,Cancelled,Omitted}`. `CostResult{accepted:bool,cards:Vec<CardId>,targets:Vec<PlayerId>}` is used only by an actual supported native cost provider; selected forced Qianlong/Weitong declarations have no invented cost. No generic arbitrary JS cost_data or VM return-result convention is introduced. Existing effect/choice machines remain the bodies; cost provider/result is an explicit native factory/API seam, not a new VM opcode or metadata wildcard.
