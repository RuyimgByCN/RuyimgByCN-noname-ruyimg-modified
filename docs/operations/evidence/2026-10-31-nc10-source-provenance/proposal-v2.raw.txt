**二、legacy JSON 忽略与 S2C wire 严格校验是两个边界。** legacy 只把 `pending_choice.source_skill` 当旧 reader 不认识的键，消耗并忽略其任意合法 JSON 值（可采用局部 IgnoredAny 等价语义）；这一步必须发生在共享 String／非空名校验**之前**。若适配器内部仍要使用共享 ChoiceRequest，交给它的字段流中不得再有该键。

该忽略只针对这一新 metadata 字段，不递归删除 GameState、options 或其它对象中恰好同名的键，不给其它未知／已知字段新增净化规则。其它字段的原类型检查、已知重复字段处理、必填字段、解析大小／深度和 JSON 语法错误保持旧语义；不能先转通用对象再重编码而悄悄折叠其它重复键或改变原校验。重复出现的新 source 键也按旧未知键处理，不能新增 legacy duplicate-source 拒绝规则。

| 新 source 的输入形态 | legacy Snapshot JSON（其它部分原本有效） | 新 S2C ChoiceRequest／Worker／IPC metadata |
|---|---|---|
| 缺失／null | 接受，None | 接受，None；None 可省略输出 |

**四、exact producer／consumer 绑定的必要谓词。** 当前 native restore 的 [唯一 active_ask 比较](/private/var/folders/b5/2mh_j5tj7m71xhcjsk2z1t4c0000gn/T/noname-nc10-legal-c661whgg/worktree/crates/engine-native/src/engine/snapshot.rs:134) 与 [scheduler 的 first-depth park](/private/var/folders/b5/2mh_j5tj7m71xhcjsk2z1t4c0000gn/T/noname-nc10-legal-c661whgg/worktree/crates/engine-native-kernel/src/resolution.rs:488) 不是同一谓词。以下只用于派生投影的准入与未来证明，**不加进 restore 接受条件，也不重排 parks／改 scheduler**。

另令 C 为 R.parks 原顺序中**首个** resume_depth==D 的 park，必须存在且 C 与 P 是同一 park，不能只是 def 名或询问形状相同。[既有 Answer 应用](/private/var/folders/b5/2mh_j5tj7m71xhcjsk2z1t4c0000gn/T/noname-nc10-legal-c661whgg/worktree/crates/engine-native/src/engine/apply_command.rs:109) 校验 id／actor／selection 后只 take open_choice、记录应答并设置 answer，不重排 parks 或改变 stack，故这是 runner 到达 park 分支时实际会选择的消费者。不得执行一步试算来“确认”它。
