建议契约的准确类型如下；这是提案类型，未写入代码：

```text
engine_native::ChoiceView::Own {
    ...existing fields...,
    source_skill: Option<&'static str>,
}
ChoiceView::Other：不增加 source_skill。

engine_api::ChoiceRequest.source_skill: Option<String>
    serde default；None 不序列化；非空 UTF-8 逻辑名才可为 Some。
NativeSession / native WS / IPC：统一键名 source_skill。
TypeScript ChoiceRequest：source_skill?: string | null。
缺失与 null 均归一为未知；旧 payload 不报错。
```

例如已知 Own 仍有 `prompt:"trigger_confirm"`、`native_kind:"confirm"`、options=[Confirm]、min=max=1、allow_cancel=true，只额外有 `source_skill:"遗计"`。未知来源省略该键；读取 null 与省略等价。没有 `source_def`、package index、module hash、frame id、PC、fuel、ancestor list 或 source-known reason。展示可以安全地按文本渲染“是否发动【遗计】？”，未知则沿用 generic 文案；不得 v-html 拼接未转义内容。ResolveChoice 仍只回 choice id／选项 token／cancel，不让客户端回传来源决定 authority。

稳定逻辑名是 **当前锁定 Catalog 中 SkillDef.name 的原值**，不是翻译文案、上游 JS id 的猜测，也不是数组下标。标准 native 的逻辑名目前就是“遗计”等既有键。唯一性必须在整个公共 catalog 上计算，不按实际实例、实际 filter 或本次匹配后的模块集合缩小。若两个 package 导出同一个 catalog name，或同名绑定不唯一，结果是 None；不得借 `by_name` 的 first-match、私有 def ordinal 或未集成的 typedSkill257 消歧。已有命名空间若本来就是唯一 SkillDef.name，可原样使用；本次不另造 package 身份字段。将来若必须支持重复名的来源显示，需另审明确的公开限定名契约，当前默认未知即可。

来源派生必须与正在产生当前询问的 exact ask 绑定，而非在 AI 里按 actual park 猜是哪类：

1. 建议沿已有 `snap::active_ask → ExpectedAsk` 派生面补一个**不持久化的来源元数据槽**，共用现有询问形状，不设第二 ledger、registry 或新的 authority。通用 ask 构造默认 None。普通 OptionalGate 只有 asked=true、inner=None、owner 与当前应答者一致时，才能以该 gate 自己的 def 读取 catalog 的逻辑名；该名字必须唯一、定义属于 native 非 VM 的 optional 询问，且名字在该 owner 的现有合法公开技能投影中。不能调用 filter、读取 once／marks／flags／私有 locals 或探秘试跑来判断可公开。
2. Engine 当前 ChoiceView 投影必须将唯一 active ask 与当前 OpenChoice 的 observer／kind／prompt／完整 options 顺序／min／max／allow_cancel 逐项核对，并由当前 OpenChoice 给出 id、由当前 Engine 给出 revision。没有唯一来源、存在两个承接者、来源与当前 ask 不符时，只给 None。新增来源不参与恢复接受／拒绝校验，不改变既有存档允许域。ExpectedAsk 本来就是派生形状；不得把新 metadata 填回 ChoiceSpec、OpenChoice、MachineSnapshot、LogEvent 或 canonical hash。
3. OptionalGate.inner=Some 时使用既有 active_ask 的内层委托语义，**不继承外层 def 的名字**。只有内层自身属于上述已证明的普通 OptionalGate、并真正匹配当前询问，才可能给出内层自己的名字；其它内层返回 None。inner 的 jiji_target／Host／RVM 询问不能借外层“遗计”盖章。另需把“exact ask 的生产者”与 scheduler 下一实际消费者的一致性列作测试和证明条件；名字不是 scheduler 路由证书。
4. 原生 Host 昆仑镜的直接同 prompt 询问是另一 producer，不能因名字或字符串相似放行。当前 `Host/asks.rs` 没有 Kunlunjing 对应分支，所读 step 虽在 SelectNature 等待确认，也不足以复用普通 OptionalGate 的来源合同。**初版该 producer 为 None**；若将来补其 exact ask 和 def_key／behavior 绑定，应独立审这条 owner 可见 UI 来源，不把普通门的字段扩成 Host 全白名单。
5. VM producer／未知自定义 producer 一律 None；即使遇到相同 prompt，也不能由该字符串制造 native 来源。当前 VM 常见询问本来是 rvm_choice 等，本文不声称当前 ABI 可任意制造 native trigger_confirm。未来若有 VM 的合法具名询问，也须另有公共来源合同；相同技能名不能授权 saved frame／PC／remaining fuel。
6. 实际源名必须来自 exact ask 的 catalog[def]，唯一反查后的定义必须仍是同一项；不用公开名字取一个无关定义后说 actual hash 与自身相等即完成绑定。最终所有 Own 接收者（本人及现有受信裁判的 full-info Own）看到同一派生结果；Other 不增加该键，普通旁观者仍按现有服务端规则无完整 choice。未知统一为 None，不公开未知原因。

这里“名字在 owner 的公开技能投影中”使用已经合法公开的 PlayerView.skills，不直接检查 private instance presence／enabled／once flag；既有投影本身处理这些状态。它是保守的来源可见性限制，不是把当前技能存储变公开。若不能从这些既有公开事实证明 owner 对这个逻辑名有权获知，便 None。

对遗计 root 的结论应精确到“有条件的有限前缀”，不能将来源字段当完整证书。源码可证明 JiJiBehavior.start 不看旧私有缓存，而创建 stage=Draw、target=None、given=0；Draw 固定摸 2，之后 Target 只按本人手牌数量、存活其它座位和 given=0 生成首次 jiji_target。若公共 deckCount≥2，不走 discard 洗牌／RNG；catalog.vm_card_history=false 时不读 drawn 累加器。调度器遇到该 WaitChoice 立即 Pending，尚未执行后面的给牌选择或父尾链。

但要把这一局部事实提升成 Engine 的安全 prefix，至少还需同时证明：source_skill 是 exact 遗计 producer；唯一逻辑名确实绑定受信的 JiJiBehavior 而非同名自定义行为，并有标准定义的 `once_per_turn=false`，不能在进入 Draw 前读 private inst.once_used；标准 native catalog 无 VM、card history 为 false；公开可见技能和装备／判定约束排除其它会在 CardsDrawn 子事件插入效果的 family；有至少一个其它存活合法目标；当前答复确实由该 producer 消费，期间没有未分类的旧 park／queue／ancestor 抢先调度。**名字本身未公开这些路径事实。** 当前 no-VM 的 trial_certifies_root 直接接受 Complete 成功结果的捷径，不足以代替这条新来源路由的前缀证明。

因此“Confirm 到首次 jiji_target 为止”是可评审的候选边界，尚不是已完成证书。不得在发现实际队列恰为空或实际 park 恰是 JiJi 后缩集合，再称公共证明成立；如现 metadata 无法排除其它调度消费者，就维持 NoCert。本稿不提公开 park count／stack depth／父技能／prefix-verified flag 来绕过缺口。

Cancel 更弱：空答使 OptionalGate 立即 Done，随后 scheduler 继续父 frame、queued triggers 和其它 parks；source_skill 只标记被取消的门，没有说明这些尾链。phase4 原 fixture 的 Cancel 正式 Accepted，不代表所有同新输入状态都如此。不能给 Cancel 固定模拟分数后省略正式尾链合法性，也不能把试算得到 Accepted 就当公共非拒绝证明。未证明尾链前，Cancel 仍应在执行未知尾链前 Opaque／NoCert；这并不改变用户正式 Cancel 的规则语义。

未知新手牌仍需单独审：`Ctx::draw_cards` 在受控路径先 note_future_draw；当前显式使用点主要阻断未来 VM 读取，不会自动保护所有 native 续行。redaction 通过内容无关隐藏池和 typed remap 处理牌引用，OptionalGate.inner 也会递归 remap，但这解决的是隐藏牌采样与引用一致性，不是 origin／fuel／旧 ancestor 合同。当前 policy_score 的直接计算使用 hp、hand_count、equipment 数和公开技能权重，所读函数没有按新卡 id 估值；仍须防后续候选枚举读取 after-view 的新手牌身份、把未知牌动作带到多层评分。建议候选前缀严格作为首次 jiji_target 的叶边界，只用已证明的公开计数投影评分，后续给牌／用牌继续需要独立知识证明；未满足前缀合法性前不能先执行探秘再丢分数。所有这些都只是后续测试／实现边界，本轮未试跑。

若将来获批，测试计划应覆盖下列具体合同，而非只看一个 green：

- projection：owner／trusted referee 的合法 native OptionalGate 具名；Other／spectator 不新增来源；唯一名字／跨包同名／空名／无公开 owner 资格／noOrigin 分别为已知或 None；source 必须等于 exact def 名，不取 first-match。
- producer 负向：外层有名字但 innerSome 的实际询问不同；两个同形 active asks；旧或错误 ask；Host 昆仑镜同 prompt；VM 同字符串或未知 producer，均不借外层／prompt 伪造来源。未知不披露原因。
- phase4 A/B/C：原 archives 与原输入证据保留并仍可恢复；按获批可见性规范验证 A 的名字、原 B/C 的 None；另用合法所属技能的刚烈／奸雄询问验证各自逻辑名。不能靠删反例或收紧 restore 绿化。
- 同来源隐私：只改隐藏 deck identity／顺序、RNG、drawn／其它缓存，保持**扩展后的完整 PolicyInput＋events**相同。若前缀确获证，budget0／48 必须两边真正 Ok、完整 Plan／stats 相等、attempts 在执行前计数、authority bytes 不变，真实 byte restore＋apply 非 Rejected。不能用两个 Err 算正向；正式 apply 可以摸到真实不同新卡，但 Plan 不应泄其原先未知身份。
- VM scalar／remaining fuel：来源相同（初版均 unknown）时原 privacy guards、旧帧默认 Deny、phase3 两效果阻断、query PC20、sampled fault 正向及 Scalar 自然反例不弱化，不改 formal 算术／fuel／restore。
- prefix 与 Cancel：Confirm 首次 Pending 后不跑未知给牌／用牌尾链；存在未证 ancestor／queued family 时拒绝。Cancel 的合法尾链须独立覆盖，否则不发证；不能暗用实际空队列作公共授权。
- wire／adapters：new→frozen WS6 reader、old/missing/null→new reader；wrong type／empty source 拒绝；Worker raw JSON、local envelope、两处 desktop response、native WS 的角色与重连 snapshot 一致；不遗漏 Main deadline_unix_ms；C2S 伪造 source 不改变执行。
- persistence：native archive／canonical hash／旧内容锁保持；legacy pending_choice 编解码不持久化或信任 source_skill；含伪造 source 的 legacy archive 仍按旧接受规则处理但不获得来源权限。不能新增持久 public certificate。
