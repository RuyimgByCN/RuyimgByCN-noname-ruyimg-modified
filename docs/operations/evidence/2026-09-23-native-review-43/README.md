# 重大事故与恢复（本轮必须记录）

**snap.rs（快照/恢复模块，约 2500 行）被一个有缺陷的批量编辑脚本
截断为 0 字节。** 根因：脚本以 `open(path,'w')` 打开文件（打开即截
断），后续编辑断言失败抛异常，未走到写入步骤——文件被清空。

**恢复方式**：无 git/编辑器历史/APFS 快照可用；以
①`archive.rs` 的 enc/dec（字节格式与字段顺序权威）、②`engine.rs`
的 restore 校验与 canonical_hash、③`kernel.rs`/`standard.rs` 的机
器 struct 与重建函数、④326 项存量测试（语义预言机）为依据，由子
代理（agent_29e7f413）以编译器+测试迭代方式重建 snap.rs **2370
行**。恢复后：engine-native 326/326、全 workspace 4,892/4,892、
**14 项 golden 哈希不变**（canonical_hash 位于未受损的 engine.rs，
语义保持一致），其他文件零改动。

**规程固化（新增记忆）**：批量编辑脚本禁止直接 `open(path,'w')`；
必须（a）全部替换成功后才写盘（写盘前不改文件），或（b）写临时
文件校验后 `os.replace` 原子替换。
