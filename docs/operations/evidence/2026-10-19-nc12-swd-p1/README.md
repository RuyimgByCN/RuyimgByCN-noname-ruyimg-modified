# P1 复测：`shahai-swd` 的慢局是**特定 seed 的路径**，不是冷启动（2026-10-19）

- 工作包：**NC12 / 八项第 8 项（性能）**
- 工具：`nc12_bench drive tier=dir:shahai-swd-upstream-noname seats=4 budget=64 lookahead=1 variant=0 seed=<42001..42005>`
- 原始输出：[run.txt](run.txt)

## 1 结果

| seed | steps | accepted | **µs/命令** | 墙钟 ms | 状态 |
|---:|---:|---:|---:|---:|---|
| 42001 | 199 | 166 | **64.76** | 10.75 | ✅ |
| 42002 | 247 | 206 | **68.67** | 14.15 | ✅ |
| **42003** | 149 | 124 | **213.19** ⚠️ | 26.44 | ✅ |
| 42004 | 341 | 285 | **64.17** | 18.29 | ✅ |
| 42005 | 332 | 276 | **67.38** | 18.60 | ✅ |

**统计**：n=5，**中位 67.38**，最小 64.17，最大 **213.19**，**极差 3.32×**。

## 2 结论（**如实**）

1. **中位 67.38 µs/命令** ✅ —— 与历史测量吻合（22 包表里 `swd` 的同类量级、上一轮 3 seed 的 **68.99**）；
2. **`seed=42003` 是 213.19**，**`seed=42007`（上一轮）是 185.47** ⇒ **两次异常发生在不同 seed** ⇒
   **不是冷启动/首次预热** ❌，而是「**某些对局路径**慢 3×」；
3. **4/5 的 seed 落在 64.17–68.67**（**极差仅 1.07×**）⇒ **`swd` 的常态是 ~67 µs**，**不是 185**；
4. ⇒ **P1 定性：特定 seed 的慢路径**（**未定位**）；**不是该包的普遍性能问题**。

## 3 下一步（**未做**）

1. 对 `seed=42003` 用 `--trace`（`nc12_bench` 有 `trace` 参数）逐步打印**步号/座位/修订号/状态形状**，找出慢在哪一步；
2. 对照 `cmd_ns` 的 p95/p99（bench 已输出 `metric=plan_ns`/`submit_ns`）看是**规划慢**还是**提交慢**；
3. 若是**某类局面**（如大量判定/连锁结算）⇒ 属**算法面**，需在 `kernel`（**未跟踪**）优化。

## 4 边界

- **5 个 seed**，不足以估计异常率（**2/7 观测到的慢局**只是样本内事实）；
- **未控制** CPU 亲和/后台负载；
- 本证据**不构成**「`swd` 慢」的结论 —— **恰恰相反，它把「慢」缩到了个别局面**。
