## 1h 标准面技能实现清单：**用 `names.rs` 常量作可靠信号**（2026-10-19）

**方法更正（本会话第 8 次更正）**：先前尝试「用上游技能键 grep 原生源码」判定实现状态 →
**不可靠**（命名不同：上游 `yiji` 在原生是常量 **`JI_JI`**，文档注释写明「郭嘉「遗计」」）→
该法得出「43 个未实现」**多为误报**（`jianxiong`/`fankui`/`jizhi`/`yiji` 等实际**均已实现**）。

**可靠方法**：`crates/engine-native/src/content/standard/names.rs` 中**每个技能常量都带文档注释**
（武将名 + 技能名），是**实现信号**；该文件共 **216 条** `pub const …: &str` 常量。
清单（含技能中文名/常量名/注释首段）见 [standard-skill-implementation.txt](standard-skill-implementation.txt)。

**用途**：①作为「该技能是否已实现」的**权威索引**；②补样本时先在此查常量名，
避免按上游键名误判（如 `遗计 → JI_JI`）。

## 1i 标准面「未实现技能」自动排查：**再次失败**（如实登记，第 2 次）

尝试「上游技能键 → 中文名 → 在原生源码中查找」以量化未实现技能 → 结果报 **未命中 0**，
但**飞影确实未实现**（样本 51 已证实，`names.rs` 索引与全库均无）→ **该法不可用** ✗。
失败原因：①上游中文名提取不完整（`feiying` 未进入映射 → 被跳过）；②「中文名出现在源码中」
无法区分「已实现」与「仅在注释/翻译表被提及」。记录见 [standard-skill-gap.txt](standard-skill-gap.txt)。

**结论（与 §1h 同一教训）**：**跨语言名称匹配**（无论上游键名还是中文名）都**不能**用来判定实现状态；
可靠做法是 **① `names.rs` 常量索引 + 逐条人工确认**、**② 按技能逐个读上游 + 查原生**（样本 51 的方式）。
